一夜发布 73 条内容，0 个新 star

语言：中文 · English

一次失败的增长实验完整复盘：31 个粉丝的账号，11 小时，73 条内容，三个仓库的 star 增长全部为零。关注与商业转化没有建立可靠测量，本文不把它们写成零。

实验窗口 2026-11-05 20:32 → 11-06 07:23（+08）。原始记录：docs/launch-autopsy-20261105.md（英文，每个数字带来源）。本文数字与原文一致，不新增任何未核实数据。

先说清楚这次实验的身份：它没有走 Growovo 的账本和执行链路。当晚的进度由三个临时脚本写成 JSON，所以部分读数只能带限定词，而不是一个整齐的零。这正是复盘要暴露的问题之一——见下面第 3 个发现。

先分清楚四个东西：发布 ≠ 曝光 ≠ 关注 ≠ 商业结果

复盘之前先立标尺。增长讨论里最常见的混淆，是把四个不同层级的结果当成一个：

层级是什么这一晚的读数
发布执行结果——内容确实发出去了73+ 条提交；36 个线程帖与 34 条回复有 ID 可核，独立帖至少 3 条确认发出，另 13 条无法确认（平台静默丢弃）
曝光渠道反馈——平台给不给看线程浏览量页面读数为 4，该读数不可信；没有独立曝光测量
关注增长信号——陌生人决定留下未完成可靠测量：账号粉丝数没有逐日落盘，不能写成 0
商业结果注册、激活、付费未提供可验证的转化数据：当晚没有注册、激活或付费的观测链路

「发了多少」是执行问题，「有没有人看」是渠道问题，「有没有人留下来」是增长问题，「有没有人用/付钱」是商业问题。执行量做得再满，也不能替代后面三层。

四层之外还有一个读数：GitHub star 增量。它是这次唯一可精确复现的硬读数——三个仓库都是 0（见下方结果表），由 GitHub API 在 11-04 和 11-06 两次读取。但 star 增量不等于关注、注册或付费；把「0 star」讲成「0 增长」，就是把未知写成零，这篇复盘不做这件事。

静默丢弃是本次最有价值的发现：任何只检查「提交调用是否成功」的管线，都会把这一晚记成 100% 成功，而实际约三分之一的独立帖从未存在。我们是被「发布后再搜一次文本」这第二道检查救回来的。

五个发现

1. 回复的触达是真的，小账号的冷启动广播不是。34 条对他人的回复全部送达；36 条线程帖几乎无人看见。31 粉丝的账号发冷线程，不缺质量，缺的是分发路径——回复之所以有效，是因为落在别人已有的受众里。

2. 数量制造不出「关心的理由」。73 条内容里没有一条能让陌生人对自己说「这解决了我手头的问题」。唯一有 218 star 的产品，star 来自完全不同的机制：此前我们用合成样本审计了约 110 个工具的 token 计量，发现 45+ 个可复现的 bug 并提了 issue，10 个修复被上游合并——star 是几个月前那件事带来的。

3. 我们自己的工具本可以抓住这个失败，但我们没用它。Growovo 的核心主张是可核验的账本（每个动作记为成功/失败/结果未知）。当晚绕过了账本，用三个临时脚本写进度 JSON——这就是「至少 3 条」带限定词的原因：我们无法从当晚自己的记录完整还原当晚。走产品的管线会把静默丢弃记成「结果未知」行，而不是让它消失。

4. 限制不是速率配额，是注意力。当日限额 50 帖 + 200 回复，我们只用了 73 条。决定什么能发出去的是平台的反自动化启发式，不是配额；但即使全部发出，结果也不会变——瓶颈从来不是产能，是没人在等。

5. 用数量「公开构建」只是写日记。「这周我们发版两次」没人能据此行动；「我们发了 73 条、一无所获、原因是这些、我们改了这些」才构成可用的公共知识。

我们改了什么

  • 取消原计划 500 帖 / 14 天的量级 campaign。
  • 每个产品先发布一个可验证的产物（一个可复现的 bug、一个数据集、一条可溯源的主张），再谈推广——陌生人可以不信我们，但可以自己验证产物。
  • X 降为公告板：每周至多 3 条，每条指向一个产物，不再公告「我们存在」。
  • 所有动作走账本，包括失败的动作。本文存在的原因恰恰是那晚没有账本，只能靠帖子 ID 反推。

这次实验不能证明什么

  • 不证明产品错了——73 条帖子是分发测试，不是产品测试。
  • 不证明 X 对所有人没用——只证明「31 粉丝 + 没有可验证产物」的账号在 X 上没用。
  • 不证明审计机制一定能复制——它成功过一次、在一个产品上、带着真实技术发现。把一次成功当公式，和这次实验是同一个错误。

Growovo 在其中的角色

它不是这次失败的解药，是防止下次失败得不明不白的工具：账本逐条记录执行量、每天落真实读数并标证据级别、异常停车等人工裁决。它不承诺平台算法给多少曝光——那一层谁也承诺不了。常见问题里写了它全自动的范围与边界；对比页写了它输在哪里、赢在哪里。
