授权范围内自动，范围之外升级

给 Growovo 产品事实、目标受众和授权范围。它发现机会、准备内容、执行已授权动作、跟进回复，并把执行回执、激活和成交分别留在记录里。

业务动作默认执行方式
搜索反馈、观察指标自动
生成内容、分析机会自动
已授权范围内的常规回复自动
新客户外联按授权人群、渠道和配额执行
高影响力公开声明风险升级审核
新账号、新权限、新渠道首次授权
金钱、合同、不可逆承诺单独审核

策略不明确时升级，不默认放行。显式 --dry-run 用于预览；它不是唯一的授权机制。当前渠道能力见平台自动执行矩阵。

一个具体任务：一次成功交付，和三次被闸门拦下的执行

输入是一个计划（demo-p0）、一个 campaign 和四个样例动作。三个可执行条目进入获批队列；含占位符的坏样本留在审批范围外，单独演示拒绝。下面是 mkt demo 的真实输出，零网络、零账号，每次运行重建沙盒，本地一秒内可复现：

步骤发生了什么结果
计划校验schema、beachhead、能力矩阵、是否超过内核日预算PASS（获批队列 3 条，日预算 100）
人审闸门campaign 属于计划 demo-p0，human_approved=false拒绝执行并停车——人审是执行前置条件
模拟人审批准mkt plan approve：署名 + 计划指纹 + 审批事件，写入 human_approved=true放行；后续写路径仍在沙盒里跑，不代表真实授权
成功投递d-000 过门禁 → 回读一致 → 离线发送（demo-memory，进程内内存）→ committed；账本补一张 L1 凭证1 条 committed，可逐条回查
三道拦截d-001 干跑未发送；d-002 占位符残留被门禁拒绝；d-003 回读不一致主动失败1 条 dry-run · 1 条 rejected · 1 条 failed，全部留痕
账本与日结果卡4 条终态与预期一致；日结果卡只读账本与三层凭证发布量 1（计划 1）；L1 有记录；L2/L3 为 UNKNOWN，不写 0

这个示例同时说明它交付什么、在哪停下：一条完整成功路径（门禁 → 回读 → 离线发送 → committed → 日结果卡），以及三处拦截（人审没通过、内容有占位符、发出去后读不回来）。发送是进程内内存模拟（demo-memory），没有任何外部发送；这里的 committed 只证明离线适配器已记录动作，不代表平台回执或转化；日卡里的 L2/L3 保持 UNKNOWN，不把未知写成 0。tests/test_demo.py 把「成功 + 三种拦截 + 可重复跑」固定成了回归测试。

常见问题

哪些动作会自动执行？

搜索反馈、观察指标、生成内容和分析机会可以自动执行；已授权范围内的常规回复也可自动执行。新客户外联按授权人群、渠道和配额运行；高影响力声明、新权限和不可逆承诺需要相应审核。

默认 Live 是不是所有动作都直接发？

不是。默认 Live 只表示已获授权的写操作不再自动退成预览。账号、动作、受众、配额和风险策略仍逐项检查；策略不明确时升级。显式 --dry-run 可随时预览。

和定时发帖工具有什么区别？

定时发帖工具执行你写好的内容。Growovo 用持久运行时维护目标、机会、资产、会话、授权、执行、回执和恢复状态，执行后继续同步回复，并把发送、激活和成交分别记录。

它说的结果，我怎么核实？

账本逐条记录执行；业务读数按 owner_declared / observed / independently_verified 分级；未知结果不自动重发。mkt demo 可零网络零账号复现授权、离线回执和拦截路径。

支持哪些渠道？

渠道能力按实际技术验收和账号授权分别公布。官方 API 与 SMTP 优先，受管 WebBridge/CDP 只在具名 owner-attested 窗口内使用，且不冒充平台许可。最新状态以平台自动执行矩阵和功能状态页为准。

要花钱吗？

工具本身 MIT 开源。运行消耗的本机资源、模型调用和第三方服务按你自己的环境计。
