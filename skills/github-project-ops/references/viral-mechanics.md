# 爆款机制与增长实证（2026-10-16 扩充版）

来源：开源项目案例库 164 条（2026-10-15 四路实网调研：近 6 周 trending 15 + 2023-26 经典 AI 爆款 26 + agent 工具链层 20 + 非 AI 对照 18 + 原库 105，星数全部当日 API 实测）+ HN 发帖人身份实证核查（20 个高星项目的最高分帖逐一对照发帖人提交史）+ 成本/计量细分位 12 项目专项。与 `growth-playbook.md`（操作流程层）互补：本文件是**传播机制与选题定位的因果层**——为什么有的项目火、星数到底量什么、渠道怎么选、演示怎么设计。

使用时机：新项目选题/定位自检（§一）、写 messaging 与主词选择（§二）、排渠道（§三）、准备发布与素材（§四§五§七）、设定增长预期（§二§十二）、命名（§九）。

## 一、爆款项目的六个共性（选题定位自检表）

| 共性 | 判据（一句话能说清就是成立） | 实证锚 |
|---|---|---|
| 1. 高频痛点，不炫技 | "人人每月都会遇到"而非"技术很难" | Ventoy 80k（做启动盘）；toktrack 反例（更快的统计 CLI 三次 Show HN 均 1-4 分——性能不是用户要的，洞察和行动才是） |
| 2. 稀缺/昂贵/禁忌能力 → 一条命令 | "X 从（贵/难/不许）变成（一条命令/免费/本地）"句式成立 | REA 262k（逆向→一句话）；VoiceStudio 68k（ElevenLabs→本地）；open-design 100k（贵 SaaS→免费） |
| 3. 72 小时内有可转发的演示 | 发布时自带三种形态之一（见 §五） | llama.cpp"30B/6GB"（HN 1311 分）；ControlNet 对比图（X 疯转） |
| 4. 命名即传播 | 转发者有转发的理由（"这就是我"）或搜索词与产品动作同构 | caveman 112k（自嘲身份）；反例：纯机制命名无画面 |
| 5. 形态极轻 | README 即产品/单文件/fork 即部署 | 技能仓库霸榜（292k/284k）；daily_stock_analysis 66k 星 83% fork 率 |
| 6. 人在浪里 | 等浪（占位等事件）或造浪（把焦虑做成梗）；无浪硬推=事倍功半 | DesktopCommanderMCP（协议前夜站坑位）；caveman 造浪 |

六项中 1+2+3 是必要条件；缺 3（可转发演示）的项目几乎必然平庸（T3 小而美 cohort 的共同缺项）。

## 二、星数心理学：三动机与天花板分档

**star 是情绪货币不是采用指标**（与 SKILL 原则 3 同源，本节给机制）：

| 点星动机 | 用户心理 | 对应产品形态 | 案例 |
|---|---|---|---|
| 好奇 | "AGI 演示我先收藏" | 首个可装的新能力 | AutoGPT 188k（复盘原话：star 反映好奇心非实用性） |
| 身份表态 | "这就是我" | 梗化命名 | caveman/ponytail/i-have-adhd |
| 收藏即拥有 | "收藏=开始学" | 内容/课程仓 | freeCodeCamp 457k、system-design-primer 374k |

反证校准：OctoPrint 9k 星但装机数百万——装机量与星数完全脱钩；判采用永远看下载/dependents/fork 率。

**天花板分档（messaging 主词选择的依据）**：

| 主词档位 | 用户得到什么 | 星天花板（实测） | 案例 |
|---|---|---|---|
| 监测/看清 | 看清问题 | ≈19k（生态基座级） | ccusage 19k；其寄生长尾全部 <500 |
| 削减/解决 | 问题变小/钱回来 | ≈83-164k | caveman 112k、ponytail 164k、rtk 83k |

规则：**对外主词选"解决档"动词（省/回/修/拿到），把"监测档"动词降为技术描述词**。佐证三件：toktrack 失败（监测做得更好也换不来星）；caveman 商业化自己把 observability 降级为功能、降本当产品；求职/隐私场景同构复现（拿 offer 的 74k vs 简历分析小工具）。

诚实边界：削减阵营多为 skill 形态且带身份表态成分，星差不能全记在 messaging 上；星数更推不出付费意愿。**预期校准**：无梗的诚实工具按"利基浪冠军"档（tokentab：434★/27% fork）设基准，不按梗级（112k）预期；先行指标=第三方引用数+采用漏斗，不是星数。

## 三、渠道 × 项目类型绑定

| 类型 | 主渠道 | 实证 |
|---|---|---|
| 基建/性能叙事 | HN | llama.cpp 989+1311 分、llamafile 1075 分、ripgrep 基准博文 |
| Agent/视觉演示 | X | AutoGPT、Cline、Compositor（HN 4 分 vs X 推到 17k 星） |
| 垂直圈层 | Reddit/论坛 | koboldcpp（r/LocalLLaMA）、ComfyUI（r/StableDiffusion） |
| 工具刚需 | GitHub 搜索+清单收录+被引用 | cc-switch 145k、ccusage、awesome-claude-code 56k |
| 中文圈 | GitHubDaily/X 中文+公众号 | HowToLiveBetter 5 周 63k |

两条铁律：①**HN 分数与星量级严重脱钩是常态**（fugleramme 2391 分→3.7k 星 vs Compositor 4 分→17k 星）——HN 决定破圈时刻，X/影响者决定星数量级，搜索决定工具刚需型长尾；评估渠道效果必须分开记账。②传播链跨平台接力（X 点燃→Reddit 刷屏→HN 沉淀），把 X 侧素材做好，HN 的策展人会来收割。

## 四、第三方发帖：筛选效应（发布策略的因果层）

**实证（HN Algolia 发帖人逐一核查，2026-10-15）：20 个有显著 HN 帖的项目，17 个的天花板帖由第三方发布**；样本里 700+ 分的帖全部不是 Show HN，而是第三方以新闻/博客/对比格式发的。goose 同日双帖对照：第三方帖 249 分 vs 内部人帖 40 分。

**机制是筛选效应不是信使效应**：策展人只在有新闻钩子的时点、以受众视角拟标题时才出手，天然滤掉作者视角的自恋帖。**作者自荐缺的是题材的事件化和标题的受众化，不是身份。**

自荐能成的三个充分条件（满足任一）：①技术奇观型（标题即故事：fugleramme 2391）；②作者有平台声誉资本（ggerganov、jart 履历）；③Launch HN/YC 格式（自带初始受众）。
自荐必然失败的三个特征：①工具型/基础设施型（HN 对"又一个 wrapper"冷淡：crawl4ai 最高 7 分、Open WebUI 23 分、Firecrawl 创始人自推 28 分）；②无新闻钩子的首发展示（"我做了 X"不如"X 发生了什么"）；③同一 URL 重复自推。

操作转译（环境就绪三件，均不依赖代发）：
1. **事件化>功能展示**：发布里的事件才是事件（厂商改口径/基准反转/里程碑数字），"我们发布 vX"不是；
2. **落地页>裸仓库**：REA 引爆帖链 rea.tools 而两个失败帖链裸 repo——对外链接给"品牌+口号"落地页；
3. **接力物>原帖**：给用户可晒的输出物（一行钱数图、终端截图梗），UGC 自发扩散。

红线：**不请人代发、不拉票**——HN 官方指南明文禁止（vote-ring 检测杀帖）；连批评帖都是放大器（反 Ollama 648 分），被批评=被事件化，回应好即可。

## 五、可复现 showcase（信任型项目的演示设计）

演示三形态：
1. **一句话击穿认知**：数字反差+价格锚点进标题（"30B 模型 6GB 内存"/"$100 训练你自己的 ChatGPT"）；
2. **前后对比图/GIF**：首屏放效果对比不放文字描述；
3. **冻结输出的可复现案例**（信任型工具唯一可用形态）：公开输入+一条命令+**已发布的期望输出**，CI 逐位比对——展示与现实不能悄悄分叉（REA 的 DX-Ball"通过 3205 个测试"同构）。

规格模板：3 个公共案例起步；输入数据合成（真实数据必须 consent+脱敏）；每个案例一个教学点（超收判定/双向核算/边界行为）；期望输出进版本库+CI 测试锁定。另配 `--sample` 式零准备入口（无 CSV 也能 60 秒出结果）。

## 六、采用形态设计

- **fork 率=可用性代理**（REA 21%、tokentab 27% vs 工程厚但门槛高的 3.7%）——"fork 来就能用"是门槛读数；
- **fork 即部署**：把产品动作做成 GitHub Actions（fork→放数据→定时跑→结果推 issue），用户 fork=获得一个零服务器的工作系统（daily_stock_analysis 66k 星 83% fork 率）；
- 涉隐私数据时 fork 即部署会撞隐私正确性（公共 fork=公开数据）：改私有仓自建方案+**公共合成数据演示 workflow**（我们的仓库公开自跑一轮，任何人可见输出形态）对冲；
- **可晒物设计**：信任型工具的可晒物是"武器化证据"（拿得出手的复算包/对质材料）而非裸数字——用户晒的是"我核过了"的身份姿态。

## 七、素材引擎（持续曝光运营件）

给潜在分享者递弹药，让他们讲自己的故事时工具恰好出现：
- **素材包八件套**：钩子标题（受众视角）/一句话回帖版/数据与出处/链接（落地页）/触发词/边界句/验证状态/使用登记；
- **监控源**：上游规则或价表漂移监测、关键词扫描命中、差评库、上游 issue 事件、社区吐槽缓存；入池门槛=有日期+有出处+可验证；
- **轮换纪律**：原创帖每条带 1 包；同包同渠道 ≥2 周不重发；含链帖遵守链接密度红线；每次使用登记归因；
- 红线：不请求转发/代发；素材只出现在自己的公开帖与回复里。

## 八、等浪清单（浪来之前备什么）

品类浪识别：同命题仓库创建日期聚集在两周窗口=浪；浪内先行者有定义权窗口。浪的触发器多为外部事件（丑闻/平台变更/爆款产品带火依赖）。等浪四件：①可转发演示（§五）；②一键安装链；③品类词占位（topics/描述/命名）；④持续更新的公共榜单（§十一）——事件爆发时"已在此监测"的仓库是唯一现成答案。事件日预案：24h 内出对照行（宣称 vs 实测，带出处）、预写无情绪句模板、通知通道就绪。

## 九、命名双引擎与可用性核查

两台引擎：描述性命名的天花板=搜索流量（工具刚需型适用，搜索词与产品动作同构）；梗式命名的天花板=转发与身份（情绪型适用）。可兼得：项目名吃搜索，内容系列名吃情绪。
改名核查五项（一次查全）：GitHub 重名（Search API）/PyPI（`pypi.org/pypi/<名>/json` 404=空闲）/npm（registry API）/域名（注册局 RDAP）/同类产品碰撞（避免同概念产品已占名——钱语义域正在快速被填占）。改名的最便宜时机=星与外链基数还小的窗口；GitHub 仓改名自动重定向、PyPI 需新包双轨一个周期。

## 十、星数卫生（2026 通胀）

判刷信号：watcher/star < 0.2‰ 且 issue/PR 活动与体量不匹配（ECC 28 万星 1.4k watcher、codebase-memory-mcp 46.6k 星 181 watcher 均高度可疑）。对标引用任何星数前先过这三看：watcher 比、活动匹配度、HN/外部讨论量。健康爆款 watcher/star 约 0.3-1%。

## 十一、Aider 模式：公共资产内容营销

方法论/基准/审计类项目的唯一被验证增长引擎：把项目做成**别人会引用的公共资产**（持续更新的基准榜/核验榜/对照表），每次外部事件（新模型发布/厂商改价）自动成为流量事件（aider 靠 LLM 编程基准报告两波 HN 202/432 分，"每次新模型发布大家都来查它的榜"）。纪律：榜单只登带出处的事实行，不做结论句——权威来自方法干净；被厂商律师函/删帖时按事实登记（Streisand 效应真实存在：gpt4free 律师函后一周星翻倍），但只有"被打"的争议才是燃料，主动挑事无效。

## 十二、本方法论的诚实边界（什么推不出什么）

1. 星数（哪怕干净）推不出付费意愿与买方接受——商业化判断必须用付款/采用/复购漏斗单独验证；
2. 监测 vs 削减的星差含形态与身份混淆变量，只作 messaging 方向假设，用同人群小实验收口；
3. 第三方发帖是分布规律不是因果律——"换人发"本身不带来流量，带来流量的是事件化+受众标题；
4. 案例均为 2026-10 前快照，引用任何数字标注（来源，日期）。
