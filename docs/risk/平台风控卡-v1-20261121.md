# 平台风控卡 v1（2026-11-21）

> 上一版风控文档是 `docs/risk/automation-compliance.md`（2026-11-03），它回答「哪些动作允许自动、哪些必须人工」，是**授权层**。
> 这一版回答的是另一个问题：**平台在 2026 年用什么信号判定一个账号是机器，触发后发生什么，我们该在哪一步停手**。
> 两份文档互补：授权层说「能不能做」，风控卡说「做到什么程度会被打」。

## 读法

每张卡固定六段：

1. **官方口径** — 原文说了什么，日期，链接，`grade`
2. **检测信号** — 平台看什么（官方公开的 / 社区逆向我方推断的，分开标）
3. **阈值与预算** — 我们能给到的具体数字
4. **触发后动作** — 检测到信号时我们的代码/人做什么
5. **我们当前实现** — 对应 `core/*.py` 的哪个函数或哪道门禁
6. **未核项** — 这轮没查到的，写清楚，不装懂

信号等级统一用三档：

| 等级 | 含义 | 处理 |
| --- | --- | --- |
| `block` | 平台明文禁止，或触发即不可恢复（封号/永久限流） | 执行前硬拦，不允许 override |
| `throttle` | 平台会降权/限流，但可恢复 | 降速、改参数、换路径 |
| `watch` | 信号存在但因果未证实 | 只记录，不改行为 |

> **一句话纪律：这里所有内容都是「避免触发」，没有一条是「如何绕过」。** 验证码、指纹伪造、代理池、马甲矩阵、AI 人性化改写这五类做法，即使在本轮采集里出现过，也不进入代码、不写成操作步骤。

## 公众号（wechat）

### 1. 官方口径

- 2026-03-27《微信公众平台运营规范》新增「非真人自动化创作行为」专项，三类违规：
  1. 使用 AI 生成、改写、拼接、搬运内容；
  2. **使用脚本、程序托管等自动化方式批量、连续发布内容**；
  3. 传播上述教程或工具。
  处罚从删文到封号。`official`（媒体逐条转述规范条文）｜`as_of 2026-03-27`｜[搜狐](https://m.sohu.com/a/1038473275_122279841)、[澎湃](https://www.thepaper.cn/newsDetail_forward_32934993)
- 2026-05 起「账号检测」新增导流维度：简介、正文、评论、消息里的联系方式、外链、二维码；命中后文章标「不符合内容推荐条件」。`craft`｜`as_of 2026-05`｜同上后续报道

### 2. 检测信号

| id | 信号 | 谁在看 | 等级 |
| --- | --- | --- | --- |
| `scripted_bulk_publish` | 固定间隔、无人值守的连续群发；同一模板批量产出 | 官方明文 | `block` |
| `diversion_fields` | 正文/简介/评论/消息中的手机号、微信号、外链、二维码 | 官方明文 | `throttle` |
| `low_read_through` | 大量读者在 30% 进度前退出 | 推断（算法侧） | `watch` |
| `ai_bulk_pattern` | 多篇文章结构、句式、配图高度同构 | 推断 | `watch` |

### 3. 阈值与预算

- 单日原创发布 ≤1 篇；两次群发间隔 ≥20 小时。
- 同一账号连续 7 天内不得出现 3 篇以上「同模板换主题」的文章。
- 正文 0 个联系方式、0 个站外链接、0 个二维码；承接只走公众号客服/企业微信组件。

### 4. 触发后动作

- `scripted_bulk_publish` → **发布路径降级为逐篇人工确认**：`action_runner` 不接受批量循环，每篇必须有一次独立的人工 `--go`。定时任务只能生成草稿，不能直接群发。
- `diversion_fields` → 发布前扫描拦截（`contact_info` 检测器），命中即 error，不允许 override。
- `low_read_through` → 不改发布参数，改内容：标题与正文承诺对齐、首屏三段给结论。
- `ai_bulk_pattern` → 拆模板：同一账号相邻两篇不得共用开头句式与配图结构。

### 5. 我们当前实现

- 内容侧：`core/platform_strategy.py` 的 `wechat` gates（`induce_follow`/`induce_share`/`contact_info`/`ad_begging`/`ai_label`/`ad_slot_floor`）。
- 执行侧：`core/platform_compliance.py` 的 `require_autonomous_write()` 与 `ALLOWED_ROUTE="official_api"`；`core/execution_policy.py` 的 `ROUTINE_ACTIONS` 里没有 wechat 的 publish，所以**公众号本来就不在自动发布路径上**——这一条 2026 新规只是把它从「产品选择」升级为「合规必需」。
- 本轮新增：`execution` gate `scripted_bulk_publish`（`detector=None`，进人工清单）。

### 6. 未核项

- 规范原文页在 `mp.weixin.qq.com` 登录墙后，本轮只核到媒体逐条转述；下一轮需要登录态截原文。

## 小红书（xiaohongshu）

### 1. 官方口径

2026-04 新规「人工 + AI 双审」，8 条红线：`official`（媒体逐条转述平台规则）｜`as_of 2026-04-27`｜[南京优创思维](https://www.ucsiwei.com/news/xiaohongshu-2026-april-new-rules-8-red)

1. 私域导流（变体词、小卡片、包裹二维码）
2. AI 生成未标注
3. 广告极限词
4. 实名与环境一致
5. 重复度（同素材多账号相似度 >50%）
6. 诱导互动/私信引流
7. 未报备商业推广
8. 虚假数据/刷量

### 2. 检测信号

| id | 信号 | 谁在看 | 等级 |
| --- | --- | --- | --- |
| `shared_environment` | 同一 WiFi 下同时在线 >3 个账号 | 官方明文（设备环境异常） | `block` |
| `login_churn` | 单日登录/登出 >2 次 | 官方明文（标「营销设备」） | `block` |
| `emulator_or_farm` | 模拟器、云手机、群控 | 官方明文（100% 识别） | `block` |
| `duplicate_material` | 同素材多账号相似度 >50%（含自我抄袭） | 官方明文（感知哈希+文本向量化） | `block` |
| `ai_unlabeled` | AI 生成/大幅改写未标识 | 官方明文（三级处罚） | `throttle` |
| `private_diversion` | 变体词（薇/卫星）、小卡片、包裹二维码 | 官方明文（语义+行为轨迹） | `block` |
| `absolute_terms` | 最好/最强/100%/彻底解决 | 官方明文（标签级拦截） | `throttle` |
| `unreported_promo` | 商业推广未走蒲公英 | 官方明文 | `throttle` |

### 3. 阈值与预算

- **一账号一设备一网络**：同 WiFi 同时在线账号 ≤3，且这 3 个必须是不同实名主体。
- 单账号单日登录/登出 ≤2 次；换设备后 24 小时内不切回。
- 同一素材（图片/文案）30 天内不得用于第二个账号；跨账号相似度按 50% 为硬线，我们内控取 30%。
- AI 参与度超过 30% 的内容必须打「AI 辅助创作」标识。
- 商业推广 100% 走蒲公英报备；未报备的「素人种草」同样在打击范围。

### 4. 触发后动作

- `shared_environment` / `login_churn` / `emulator_or_farm` → 立即停止该设备上的一切发布，账号进入 7 天静默期；不在同一网络下再登录第二个号。
- `duplicate_material` → 阻断发布；要求换素材或换角度，不允许「改标题重发」。
- `ai_unlabeled` → 阻断发布直到加标识；已有内容出现限流时优先自查标识，不要先怪算法。
- `private_diversion` / `absolute_terms` → 发布前检测拦截（`contact_info`/`absolute_claim`）。
- `unreported_promo` → 转蒲公英流程，不直接发。

### 5. 我们当前实现

- 内容侧：`core/platform_strategy.py` 的 `xiaohongshu` gates（`contact_info`/`induce_follow`/`ai_label`/`anxiety_sell`/`clickbait`）与 `repost_within_90d` execution gate。
- 环境侧：**当前没有代码实现**。`core/browser_attach.py` 只做单浏览器单账号附着，不管理多账号环境；这一条靠运营纪律，不靠代码。
- 本轮新增：content gate `duplicate_material`（`detector=None`，进人工清单）。

### 6. 未核项

- 8 条红线的平台原文页未拿到，只有媒体逐条转述；「同 WiFi >3 账号」的原文表述待核（可能是「异常设备环境」的描述性说法，不是精确阈值）。

## Reddit

### 1. 官方口径

- free tier 100 QPM；self-service 应用申请 2025-11-11 关闭；app label 2026-03-31 上线；训练模型需书面批准。`official`（API 条款 + 官方公告转述）｜`as_of 2026-08`｜[RedditAPI](https://www.redditapis.com/blogs/reddit-bot-rules-2026)
- 2026-09-30 r/redditdev 官方时间表：2026-10-31 停止接受新 public API 申请；2027-01-12 开始切断未登记应用；**2027-03 全部 public API 关闭**；2026-11-13 RSS 停止支持。`craft`（多家二手一致转述官方帖）｜`as_of 2026-09-30`｜[Reduck](https://reduck.ai/use-cases/reddit-api-alternatives)、[BoomReddit](https://boomreddit.com/glossary/reddit-api/)
- 9:1 自我推广规则：每 10 条内容最多 1 条自我推广。`official`｜多年未变

### 2. 检测信号

| id | 信号 | 谁在看 | 等级 |
| --- | --- | --- | --- |
| `self_promo_ratio` | 自我推广占比超过 1/10 | 官方明文 | `throttle` |
| `api_shutdown_2027` | public API 2027-03 关闭 | 官方时间表 | `block` |
| `cqs_low` | Contributor Quality Score = Low/Lowest | 推断（AutoMod 配置） | `throttle` |
| `karma_gate` | 未达 sub 的 comment karma / 号龄门槛 | 推断（AutoMod 配置） | `throttle` |
| `shadowban` | 帖子零曝光、零互动，但账号无通知 | 推断（平台行为） | `watch` |
| `new_account_burst` | 新号短时间多 sub 发帖 | 推断 | `watch` |

### 3. 阈值与预算

- 自我推广内控按 **20:1**（官方 9:1 是底线，不是目标）。
- 目标 sub 分档预算：小型 sub 可直接参与；中型先 50–200 comment karma；大型 200–500 comment karma + 14–30 天号龄。
- 单账号单日 ≤3 帖、≤10 评论；同一 sub 24 小时内 ≤1 帖。
- **2027-01-12 前必须完成通道迁移**：这是硬截止日，不是建议。

### 4. 触发后动作

- `api_shutdown_2027` → **通道级熔断**：2026-12-31 前把 Reddit 自动发布标记为「即将失效」；2027-01-12 起自动发布禁用，只保留人工发布。迁移目标是 Devvit（平台内应用），不适合外部发布工具，因此现实出路是人工发布 + 手动记录。
- `self_promo_ratio` → 发布前计算最近 20 条内容的推广占比，超 5% 即拦。
- `cqs_low` / `karma_gate` → 不在该 sub 发帖，转 comment 参与；karma 未达标前不做任何发布。
- `shadowban` → 用未登录浏览器访问 `reddit.com/user/<name>`，看不到自己的帖子即视为被 shadowban；触发后停发 14 天并申诉，不换号重来。

### 5. 我们当前实现

- 内容侧：`core/platform_strategy.py` 的 `reddit` 4 条 gates。
- 执行侧：`core/execution_policy.py` 的 `ROUTINE_ACTIONS` 含 `reddit:publish`/`reddit:reply`；`core/platform_compliance.py` 的 `AUTHORIZATION_NAME="platform-authorization.json"` 管授权。
- **缺口**：没有 `api_shutdown_2027` 的到期熔断代码；没有 shadowban 检测。本轮只写进风控卡与文档，不写实现（需要登录态与外部请求，超出当前产品边界）。

### 6. 未核项

- 2026-09-30 官方时间表原文帖（r/redditdev）未直接读到，只有多家二手一致转述。
- 各 sub 的 AutoMod 门槛是社区汇总，不是官方文档。

### 1. 官方口径

- LinkedIn 用户协议禁止 scraping、bot 操作与未授权自动化；具体限额不公开。`official`｜长期有效
- 2026 年社区逆向阈值：连接请求 20–25/日、100/周、pending <500；新号先养两周，之后每周 +5。`lead`｜`as_of 2026-07-20`｜[Yalc](https://www.yalc.ai/blog/linkedin-automation-limits-and-rules/)

### 2. 检测信号

| id | 信号 | 谁在看 | 等级 |
| --- | --- | --- | --- |
| `browser_plugin` | 浏览器插件式自动化 | 推断（主要触发源） | `block` |
| `invite_burst` | 单日邀请 >25、单周 >100 | 推断 | `throttle` |
| `pending_backlog` | pending 邀请 ≥500 | 推断 | `throttle` |
| `profile_scrape_burst` | 短时间大量查看他人主页 | 推断 | `throttle` |

### 3. 阈值与预算

- 连接请求 ≤20/日、≤100/周；pending 保持 <500。
- 新号前 14 天不发邀请；之后每周 +5，直到稳定在 20/日。
- 不使用任何浏览器插件；自动化只走官方 API（当前 Growovo 只有 `linkedin:message` 在 `ROUTINE_ACTIONS`）。

### 4. 触发后动作

- `browser_plugin` → 不安装、不运行；`require_user_visible_cdp()` 与常驻 browser-attach 门均拒绝 X 的非 API 网页脚本写。
- `invite_burst` / `pending_backlog` → 计数闸门：日/周配额用尽即停，pending 超 480 停止新增邀请。
- `profile_scrape_burst` → 人工浏览，不批量。

### 5. 我们当前实现

- `core/platform_strategy.py` 的 `linkedin` 3 条 gates；`core/execution_policy.py` 只有 `linkedin:message`，没有 publish/reply，因此发布侧天然受限。
- 连接请求配额**没有代码实现**，属于运营纪律。

### 6. 未核项

- LinkedIn 官方从未公布具体限额，20–25/日、100/周来自社区长期观察，不是官方数字。

## GitHub

### 1. 官方口径

2026 年配额未变：认证 5000 请求/小时、未认证 60/小时、Search API 30/分钟、REST 二级限流 900 points/分钟、并发 100。`official`｜`as_of 2026-10`｜[GitHub Docs](https://docs.github.com/rest/using-the-rest-api/rate-limits-for-the-rest-api)、[Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-cloud/dev/dev-proxy/concepts/github-api-rate-limit-exceeded)

### 2. 检测信号

| id | 信号 | 谁在看 | 等级 |
| --- | --- | --- | --- |
| `primary_rate_limit` | 5000/h 用尽 | 官方 | `throttle` |
| `secondary_rate_limit` | 900 points/min 用尽 | 官方 | `throttle` |
| `search_quota` | Search API 30/min 用尽 | 官方 | `throttle` |
| `unauthenticated` | 未认证请求 60/h | 官方 | `throttle` |

### 3. 阈值与预算

- 每次批量操作前读 `X-RateLimit-Remaining` 与 `X-RateLimit-Reset`，剩余 <10% 即停。
- Search API 单次循环 ≤20 次查询，留 10 次余量。
- 禁用未认证请求做任何批量操作。

### 4. 触发后动作

- 任一限流命中 → 按 `X-RateLimit-Reset` 等待，不做重试风暴；二级限流额外退避 60 秒。
- 连续 3 次二级限流 → 当日停止该仓库的一切写操作。

### 5. 我们当前实现

- `core/execution_policy.py` 的 `github:reply`/`github:publish`。
- 限流参数**没有代码实现**；GitHub 操作当前以人工/低频为主，未触发过。

### 6. 未核项

- 无。
