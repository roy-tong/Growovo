# 转化（Conversion）

> 代码：`core/conversion.py` · CLI：`mkt deal add|advance|qualify|list|next|funnel|quote|objections`
> 核心判断：**转化不是“多跟进”，是“每个阶段只做一个动作，做不了就停”。**

## 0. 用 Askovo 的链条读转化

转化不是“多跟进”，是一条业务链：

```
场景（他收到一条引用原话的消息）
  → 用户（FinOps/财务/AI 交付方）
  → 痛点（分不到团队/对不上发票/残余没人负责）
  → 需求（先看一个样本，再决定要不要付）
  → 动作（问资格 → 给样本 → 请读回 → 报价 → SOW → 交付）
  → 商业（付费 → 复购）
```

每个阶段都要回答四个问题：

1. **业务上意味着什么**：他愿意花时间？愿意给数据？愿意签字？
2. **我们知道什么/还缺什么**：回复、数据、读回、预算；
3. **为什么是这一个动作**：不是“多跟进”，是“下一步只做一件”；
4. **什么情况下放弃**：3 天没回、不愿给数据、3 次不决。

阶段名是代码，业务含义才是判断；默认输出是业务语言，JSON 才保留阶段码。

## 1. 为什么“聊得好”不是转化

上一轮的真实断点不是“没人回”，是“回了之后没有下一步”：

```
9 个实质回应 → 跟进 → 0 → 商业询问 → 0 → 付费 → 0
```

复盘把它归因为“渠道无效”，但数据说的是另一件事：**有 5 个人给过实质回应，
包括邀请提 PR、找出 3 个真缺陷、直接改写 spec 措辞，之后没有任何一次跟进。**
不是没机会，是机会停在“聊得好”。

转化要解决的就是这一步：把“聊得好”变成一个有阶段、有证据、有下一个动作的管道。

## 2. 阶段：14 个，不多不少

```
sourced → contacted → engaged → qualified → sample_offered → sample_received
→ sample_delivered → readback → quoted → sow_sent → paid → delivered → repeat
                                                                      ↘ lost
```

| 阶段 | 进入条件 | 证据 |
|---|---|---|
| sourced | 有名字、有来源、有“他最近在做什么” | 来源链接 |
| contacted | 第一条消息发出 | 平台/时间/内容 |
| engaged | 对方回了，且不是礼貌性回复 | 回复原文 |
| qualified | 五项资格至少中三项 | 资格表 |
| sample_offered | 给了样本范围（1 个归属单元/24h/3 页） | 范围一页纸 |
| sample_received | 收到发票 + 成本导出 + 用量导出 | 文件清单 |
| sample_delivered | 3 页差异报告交付 | 交付记录 |
| readback | 对方说“这就是我月底要交的东西” | 读回原话 |
| quoted | 报价（$1,500 诊断包），只出现一次 | 报价记录 |
| sow_sent | 一页 SOW 发出 | SOW 文件 |
| paid | 到账 | 收款记录 |
| delivered | 7 个文件交付 + 读回 | 交付包 |
| repeat | 第二期/第二供应商 | 合同/付款 |
| lost | 明确拒绝或无回应判弃 | 原因 |

**为什么这么细**：粗管道会把“回了”当成“快成了”。样本、读回、报价、SOW、到账
是五个不同的证据；少一个，就不能说“在转化”。

## 3. 资格：五项，至少中三项

| # | 项 | 问什么 |
|---|---|---|
| 1 | trigger | 有触发事件 + 日期（发票到了/CFO 要数/续约/账单异常） |
| 2 | contactable | 责任人可沟通（本人发帖/回帖/熟人引荐） |
| 3 | data | 能拿到发票 + 至少一份导出 |
| 4 | cost | 现有办法有成本（表格/工程师工时/顾问费） |
| 5 | price | 接受明确范围与价格（或至少愿意听） |

**为什么是 3/5**：五项全中是理想客户，但首单往往缺一两项；缺 `data` 时先给
“你自己跑、我审输出”；缺 `price` 时先给样本再报价。**缺 trigger 或 contactable，
基本不用聊**——没有触发事件就没有预算，联系不上就没有下一步。

## 4. 下一个动作：每个阶段只给一个

| 阶段 | 下一个动作 | 为什么 | 停止 |
|---|---|---|---|
| sourced | 第一条消息：引用原话 + 两个真问题 | 先给判断，不介绍产品 | 无 |
| contacted | 第 3 天跟进一次，只补一个具体发现 | 不追第二次 | 3 天没回 → 判弃 |
| engaged | 问三个资格问题 | 问完再给样本，不跳步 | 拒绝 → lost |
| qualified | 给免费样本：1 个归属单元/24h/3 页 | 先给范围，再要数据 | 不给数据 → lost |
| sample_offered | 确认数据清单 | 数据不到就不开工 | 7 天不到 → lost |
| sample_received | 跑样本，24h 出 3 页 | 先给差异，不给结论 | 无 |
| sample_delivered | 请对方读回 | 读回才算交付 | 不读回 → 追一次 |
| readback | 报价 $1,500，一页 SOW | 报价不是追问，是给决定 | 拒绝 → lost |
| quoted | 第 3 天跟进一次，问决定/障碍 | 降价只缩范围 | 3 次不决 → lost |
| sow_sent | 确认签字/付款 | 不催第三次 | 3 次 → lost |
| paid | 交付 7 个文件 + 读回 | 先交付，再谈复购 | 无 |
| delivered | 30 天后问复购 | 用上期结果开场 | 无 |
| repeat | 扩到多账期/多供应商 | 先复现，再加量 | 无 |
| lost | 停；记原因；90 天后可再试一次 | 不换号、不纠缠 | — |

**“等”也是动作**：contacted 未满 3 天、quoted 未满 3 天，系统会说“等”，
而不是让你“再跟进一下”。等，是为了不让跟进变成骚扰。

## 5. 异议：九个分支，每个都有“什么时候走开”

| 异议 | 怎么回 | 什么时候走开 |
|---|---|---|
| 已经有工具了 | 问：它能不能发票↔成本导出行对行、给每个差异一个原因码？ | 对方能拿出 invoice-level reconciliation 的证据 |
| 太贵了 | 缩范围，不降价：一个供应商/一个归属单元；或先免费样本 | 预算 <$500 且无合规/关账压力 |
| 数据太敏感 | 本地跑只给输出；只给一个单元；NDA+脱敏+删除 | 连脱敏导出都不给，且不愿自己跑 |
| 今年没预算 | 问预算归属和续约/关账时间；压到部门费用 | 没有日期、没有 owner、没有触发 |
| 先发资料 | 不发 deck，发一页 checklist + 一个问题 | 连续两次只要资料、不回答 |
| 现在不是时候 | 要一个具体日期和触发事件 | 没有日期 |
| 要老板批 | 给审批人一页：范围/价格/验收/边界；约三方会 | 审批人始终不出现 |
| 供应商说他们能对 | 供应商不会替客户做跨家对账，也不会为发票签字 | 对方只需要供应商自证 |
| 我们自己做 | 同意云侧自建常见；问 AI 那一段谁维护、月末 7 天谁盯 | 已有稳定运行的 AI 对账流程 |

**异议不是拒绝**：它是信息。你要么拿到一个日期，要么拿到一个走开的理由；
两者都比“再想想”好。

## 6. Offer 阶梯：从免费到月度

| 档位 | 范围 | 价格 | 周期 | 作用 |
|---|---|---|---|---|
| 免费样本 | 1 供应商 × 1 账户 × 1 账期 × 1 归属单元 | $0 | 24h | 信任的最小单位 |
| 诊断包 | 同上，全部归属单元 + 7 个文件 | $1,500 | 5 天 | 首单 |
| 月度包 | 每账期重复 + 环比 | $900/期 | 3–5 天 | 复购 |
| 季度试点 | 3 期 + 映射 + 复盘 | $4,000 | 6 周 | 企业采购 |

**为什么免费只做样本**：完整账期是收费项；免费做完整账期会把服务变成白嫖。
**为什么按账期收费**：买家的仪式是月度关账；订阅制会让他觉得“又多一个平台”。
**为什么不按节省分成**：归因争议；首单要的是“有人付钱”，不是“分成最优”。

## 7. 报价：一页 SOW，七个文件

```
01_scope.md            范围、假设、客户提供物、验收
02_mapping.csv         key/workspace → 团队
03_recalc.csv          四段价复算
04_reconciliation.csv  发票行 ↔ 成本行 ↔ 复算行
05_residual.md         对不上的钱：金额、原因、缺什么、找谁要
06_cfo_onepager.md     总额、驱动、Top 3、下月动作
07_signoff.md          复算说明、口径、限制、签署栏
```

**验收五条**：分摊合计=发票总额（到分）；每笔差异有原因码；重跑一致；
财务能入账/计提；残余单列。
**不做**：不承诺追回/节省/ROI；不做实时监控；不做系统集成。

## 8. 漏斗：看什么、不看什么

`mkt deal funnel` 给：

- 各阶段**当前存量**；
- 按 history 曾进入阶段计算的相邻 **cohort 转化率**（不是当前存量相除）；
- sourced cohort 中曾进入 paid 的比例；
- 卡住的对象（超过阶段阈值天数没动）。

**能看**：哪一步掉得最多、哪个对象卡住、平均周期。
**不能看**：因果。一个阶段转化率高，不代表你的话术好；可能是名单挑得好。
**不能承诺**：从 30 条私信推“下个月 10 个客户”；样本太小，且没有回填。

## 9. 五个常见错误

1. **把“回了”当“快成了”**：回复只是 engaged，离付费还有 6 个阶段。
2. **免费做完整账期**：一次白嫖会变成常态；免费只做样本。
3. **降价不缩范围**：降价会把“账期包”变成“廉价外包”，下一单更难。
4. **不开口**：上一轮 9 个实质回应、0 次商业询问；第 3 次互动必须开口。
5. **追第三次**：同一对象最多 2 次动作（首发 + 1 次跟进）；第三次是骚扰。

## 10. 产品模型

`core/conversion.py` 提供：

- `STAGES` / `TRANSITIONS`：阶段机；非法跳转直接拒绝；
- `qualify()`：五项打分；
- `next_action()`：每个阶段一个动作、一个截止、一个停止；
- `OBJECTIONS`：九个异议 + 回应 + 走开条件；
- `OFFERS`：四档 offer；
- `Deals`：`deals.jsonl` 以 `growovo.deal_event` 追加，`all()` 生成当前投影并兼容旧行；普通新建只能从 sourced；所有 `advance` 目标都要求证据，进入 qualified 前必须通过资格，quote 只允许当前 readback；paid 可另附 `verification_method/ref`；
- `funnel()`：当前阶段存量、history cohort 转化率、卡住对象；两者不混用。

CLI：
```bash
mkt deal add --contact vrv-01 --name "Dalius" --campaign verovo-3day
mkt deal advance --id deal-0001 --stage engaged --by roy --evidence "reddit reply"
mkt deal qualify --id deal-0001 --trigger --contactable --data --cost
mkt deal next
mkt deal funnel
mkt deal quote --id deal-0001 --offer diagnostic
mkt deal objections
```

## 11. 边界

- 阶段是记录，不是预测；`paid` 才叫付费；
- 漏斗是描述，不是因果；
- 报价是给决定，不是追问；接受报价 ≠ 付款；
- 免费样本不是需求证明；样本交付 ≠ 付费意愿；
- 转化率只在样本足够时有意义；10 个对象以下的比率只当线索。
