# 方案模板与交付物契约库

> 模板的目的不是让 Agent “写满一份文档”，而是让工作具备共同输入、专业内容、质量验收和下游可用性。每个模板都必须实例化为带版本的 Deliverable。

## 0. 模板如何运行

### 0.1 四层结构

```text
Template（稳定身份，如 T12 ABM 方案）
  └─ TemplateVersion（不可变版本，如 1.3.0）
       ├─ slots：字段类型、必填、默认值、数据来源
       ├─ renderers：Markdown / JSON / 表格 / 执行请求
       ├─ rubric：逐项质量验收规则
       └─ permissions：谁能编辑、审核、批准、接收
              ↓ 实例化
DeliverableVersion（本次真实交付物）
  └─ AcceptanceReview（通过 / 返工 / 不适用 + 证据）
```

已被 WorkOrder 引用的 TemplateVersion 不可原地修改。内容变更产生新版本；如果影响已批准的事实、对象、预算、范围、执行载荷或验收条件，相关审批必须失效并重审。

### 0.2 所有方案共同继承的 Base Envelope

| 字段 | 要求 |
|---|---|
| `deliverable_id / template_id / version` | 稳定 ID、模板身份与不可变版本 |
| `work_order_id / objective_id` | 归属工作与运营目标 |
| `business_context_ref` | Askovo 或用户上下文快照及版本，不读取“最新浮动态” |
| `owner / contributors / receiver` | 一个主责 Owner、协作者和交付接收人 |
| `subject / scope / exclusions` | 人、账户、机会、订单、商家、开发者等主体与明确非目标 |
| `time_window / timezone / due` | 执行与观察窗口、时区、到期时间 |
| `input_artifacts` | 输入交付物 ID + 版本；不接受无版本“见上一个文件” |
| `evidence_refs` | 事实、数据、客户原话、授权、规则等可追溯来源 |
| `result_metrics / process_metrics / guardrails` | 指标 ID 与版本；不在正文随意改公式 |
| `budget / permissions / risk` | 成本范围、数据 / 账号 / 动作权限、风险级别 |
| `approvals` | 审阅人、范围、版本、时间、有效期与拒绝原因 |
| `handoff` | T31 交接单；无下游也要写“最终归档接收人” |
| `outcome_status` | 待观察 / 部分观察 / 已观察 / 不可判断；不能继承发送状态 |

### 0.3 通用验收

- 必填字段完整，未知写“未知 + 补数 Owner + 日期”，不编造；
- 事实主张有来源，产品 / 客户 / 财务数字与来源一致；
- 目标、主体、排除项、窗口、预算、Owner 和下一决策明确；
- 每个执行项都有接收人、验收条件和失败分支；
- 需要外部动作时，另行生成 Action Request，不在文档审批中隐式授权；
- 每个必需 rubric 项只能为 `pass / fail / not_applicable`，NA 必须写理由；
- 提交、审核通过、接收方签收、业务结果观察是四个不同事件。

## 1. 通用管理与协作模板（T01 / T02 / T31 / T32）

### T01 · 运营目标与 KPI 契约

**用于**：所有岗位，尤其 16/18/24/34/38/43/44。
**专用字段**：业务问题、目标主体、基线及窗口、目标或学习问题、主结果指标、辅助结果、过程指标、护栏、资源 / 预算、数据来源、目标 Owner、复盘时间。
**验收**：只设一个主结果；基线未知时明确未知；每个指标已在字典注册；目标不是把动作量换个名字；能回答“结果不好时谁决定什么”。

### T02 · 工作委托单（Work Order）

**用于**：所有岗位。
**专用字段**：工作触发、业务目的、输入契约、SOP 版本、交付物列表、步骤 / 依赖、RACI、人工时间、预算、权限、风险、里程碑、异常 / 停止、交接、结果观察计划。
**验收**：没有输入、Owner、交付物、DoD 或接收人的任务不能 ready；依赖未验收不能执行；步骤风险与权限匹配。

### T31 · 跨岗位交接与验收单

**用于**：所有上下游交接。
**专用字段**：from / to role、主体 ID、业务背景、已完成事实、交付物及版本、原话 / 行为 / 数据证据、已做动作、对外承诺、未决问题、接收标准、SLA、接收决定、拒收原因、返工步骤、下一动作与时间。
**验收**：只有接收人能 accepted；拒收必须定位缺项并回退到具体 SOP 步骤；超时升级；发送通知不等于交接完成。

### T32 · 复盘与规则变更单

**用于**：所有岗位与 SOP 治理。
**专用字段**：原目标 / 假设、实际三层结果、投入与成本来源、做对 / 做错、替代解释、数据限制、继续 / 停止 / 修改决定、SOP / 模板 / 指标 / 权限 diff、影响范围、审批、回滚、下次验证。
**验收**：不是“加强 / 优化”口号；至少一个具体规则 diff 或明确“不变及理由”；机制解释与事实分开；版本变更有人审。

## 4. 交付物状态与证据要求

### 4.1 状态

```text
draft → submitted → in_review → accepted → handed_off → observed → archived
             ↓ fail                ↑ rejected
             └──── revise ──────────┘
```

`released/published` 是对外动作结果，不替代 `accepted`；`observed` 只表示按预定方法观察到结果，不自动表示因果或成功。

### 4.2 不同交付物的验证器

| 类型 | 必要验证 |
|---|---|
| 内容 / 文案 | 事实、链接、数字、语气、权利、CTA 与承接一致 |
| 设计 / 视频 | 文件可打开、规格、字幕 / alt、版权 / 肖像、版本 |
| 代码 / 示例 | 环境固定、真实运行、预期结果、测试、secrets / 安全 |
| 数据 / 分析 | 查询 / 数据集版本、重跑、分子分母、窗口、限制 |
| 销售 / POC | 客户 / 内部范围确认、逐项证据、承诺与未决风险 |
| 财务 / 收入 | 财务或订单来源、净额 / 成熟窗口、对账与退款 |
| 服务 / 客户交付 | 客户接收、问题解决 / 价值事件读回，不用“已发送”替代 |
| 自动化 | 授权、沙盒、小样本、幂等、回读、异常、回滚、运行日志 |

### 4.3 模板治理指标

模板系统自身的健康指标包括：一次验收通过率、平均返工轮次、拒收原因分布、过期模板比例、缺失证据字段分布、SOP 步骤阻塞时长、模板被实际业务采用率。模板数量、生成字数和 SOP 页数不是健康指标。
