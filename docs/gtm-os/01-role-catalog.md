# 岗位能力、KPI 与 SOP 目录（07–46）

> 本目录是产品能力规格，不是招聘 JD，也不是已验证的行业基准。每个岗位族都给出通用骨架；实际运行必须叠加企业、行业和平台 Overlay。目标值不得由系统凭空生成。

## 0. 阅读约定

- **结果 KPI**：岗位对业务结果的贡献；**过程 KPI**：工作是否高效合格；**护栏 KPI**：防止追结果时伤害用户、品牌、利润或合规。
- 比率默认保存 `分子 / 分母`、去重主体、资格条件和时间窗；分母为 0 时显示不可计算。
- SOP 中每一步都应在系统内展开为 `输入 → 操作 → 输出 → DoD → 异常`；文中的箭头是摘要，不允许实现成只有标题的 checklist。
- 模板编号见 [02-template-library.md](02-template-library.md)。T01（目标与 KPI）、T02（工作委托）、T31（交接验收）、T32（复盘变更）为所有岗位共用。
- 岗位效果与执行验证分开：`SOP 已配置`、`动作已跑通`、`业务结果已观察`是三种不同状态。

# B. 品牌、内容与传播运营

## 07. 品牌营销

**使命与职责**：在已确认的定位下形成一致的品牌表达与记忆；规划品牌战役、整合传播、品牌资产和联名 / IP；协调创意、媒体、社媒、公关与销售使用同一事实和视觉规范；管理品牌预算与资产版本。

**KPI**
- 结果：目标受众品牌认知 / 偏好变化（同一测量方法前后对比）；品牌搜索或直接到访的合格访问；品牌 campaign 带来的激活 / 合格线索；有效触达成本。
- 过程：campaign 准时交付率、核心消息在各渠道的一致率、品牌资产复用率。
- 护栏：事实 / 版权错误数、负面反馈与投诉、预算偏差、过度曝光频次。声量本身不等于品牌信任。

**标准 SOP**：①确认业务目标、受众和上游定位版本 → ②盘点既有认知、资产、渠道与约束 → ③形成品牌 big idea、消息屋和 campaign 架构 → ④完成创意、渠道、预算和测量设计 → ⑤业务 / 品牌 / 法务验收后分渠道执行 → ⑥监测认知、合格行为和负面信号 → ⑦复盘并更新品牌资产规范。

**核心产出 / 模板**：品牌传播方案、消息屋、整合 campaign brief、品牌资产清单；使用 **T03**。

**交接 / 人审 / DoD**：向 08/09/11/12/19 提供已批准消息屋与资产；向 18/27 提供销售可用版本。品牌承诺、对外主张、联名和高额预算必须人审。DoD：每项主张有事实来源，渠道 Owner 收到适配包并签收，测量口径事前定义。

## 08. 公关与媒体关系

**使命与职责**：管理新闻价值、媒体关系、企业传播、思想领导力、舆情和危机；维护事实表、发言人、媒体名单和问答；确保公开回应准确、及时且经过授权。

**KPI**
- 结果：目标媒体有效报道数及核心消息准确带出率；报道后合格访问 / 咨询；危机首次响应与遏制时间；高质量媒体关系覆盖。
- 过程：媒体请求响应 SLA、事实核验及时率、Q&A 完备率。
- 护栏：更正 / 撤稿率、失实表述、未授权发言、舆情升级率。不能以转载总量代替报道质量。

**标准 SOP**：①确认议题、事实和披露边界 → ②判断新闻价值、舆情风险与响应级别 → ③准备新闻稿、事实表、Q&A 和发言人 → ④法务 / 业务 / 高管按风险审批 → ⑤定向媒体沟通并记录反馈 → ⑥监测报道、错误和舆情扩散 → ⑦更正、复盘并更新媒体与危机手册。

**核心产出 / 模板**：新闻传播方案、媒体 pitch、新闻稿、危机响应一页纸、舆情日志；使用 **T04**。

**交接 / 人审 / DoD**：从 07/09/27/38 获取可公开事实和客户授权；向 12/15/40 下发统一答复口径。危机、法律、隐私、人事和财务议题必须具名审批。DoD：事实、时间线、发言人、审批和下一次更新时间齐全。

## 09. 内容运营

**使命与职责**：规划选题、栏目、编辑日历、内容生产与分发；运营 PGC / UGC、知识内容和专题；管理内容质量、生命周期、复用与衰退；让内容服务明确的用户任务和业务阶段。

**KPI**
- 结果：内容后完成目标任务的用户数 / 率；内容辅助的激活、合格线索或留存；有效内容资产数。
- 过程：按期发布率、一次验收通过率、生产周期、更新及时率、复用率。
- 护栏：事实错误、重复 / 拼凑、过期内容、版权问题、低质量互动。阅读 / 曝光只作传播诊断。

**标准 SOP**：①接收受众任务、消息规范和业务目标 → ②盘点搜索需求、销售问题、客服问题和既有内容 → ③建立选题优先级与编辑日历 → ④制作 brief、事实包并分配生产 → ⑤编辑验收、发布和跨渠道复用 → ⑥跟踪互动、任务完成与内容衰退 → ⑦更新 / 合并 / 下线并修订选题规则。

**核心产出 / 模板**：内容营销方案、编辑日历、内容 brief、内容审计表；使用 **T05**。

**交接 / 人审 / DoD**：向 10/11 发生产 brief，向 12/14/35/46 交付渠道适配源文件；事实主张和产品承诺需业务 Owner 审批。DoD：目标用户任务、事实来源、CTA、复现 / 阅读路径和观察事件明确。

## 10. 文案与编辑

**使命与职责**：把事实和价值主张写成适配场景与阅读阶段的文案；负责广告、品牌、SEO、技术、脚本、邮件、社媒和产品文案；编辑事实、逻辑、语气、可读性和行动引导。

**KPI**
- 结果：同口径文案版本带来的目标行为变化；销售 / 客服可复用率；技术文案任务完成率。
- 过程：一次审过率、平均修改轮次、准时率、事实保留通过率。
- 护栏：夸大 / 无依据主张、语义遗漏、品牌语气偏差、抄袭与敏感表述。

**标准 SOP**：①确认读者、触发场景和唯一行动 → ②读取事实包、禁用语和平台约束 → ③提出角度、标题和结构 → ④完成正文与 CTA → ⑤做事实、链接、数字、权利和语气 lint → ⑥业务审阅并生成渠道版本 → ⑦根据任务结果复盘具体句段，而非只看点击。

**核心产出 / 模板**：文案交付包、事实核对表、渠道改写稿；使用 **T05 / T06**。

**交接 / 人审 / DoD**：向 11/12/14/17/25/35 交付定稿和可编辑源稿；对外新主张必须人审。DoD：每个事实可回溯，CTA 与承接页一致，没有未替换占位符。

## 11. 创意与视觉制作

**使命与职责**：将 campaign / 内容策略转为视觉、视频、动效和广告素材；管理创意概念、脚本、分镜、制作、适配、素材命名、授权和版本；支持创意实验。

**KPI**
- 结果：素材带来的合格观看、落地页行动或激活；被业务渠道采用并复用的素材比例；实验中可解释的创意表现。
- 过程：制作周期、准时率、返工率、规格一次通过率、单位合格素材成本。
- 护栏：品牌规范错误、音乐 / 肖像 / 素材侵权、误导性画面、过度制作成本。

**标准 SOP**：①接收已批准 brief 和事实包 → ②提出概念、参考与脚本 / 分镜 → ③确认制作范围、预算、权利和渠道规格 → ④制作母版及适配版本 → ⑤检查事实、品牌、字幕、规格与授权 → ⑥交付并登记素材指纹 / 版本 → ⑦按创意变量复盘并沉淀可复用组件。

**核心产出 / 模板**：创意 brief、脚本分镜、素材清单与授权表；使用 **T06**。

**交接 / 人审 / DoD**：向 12/17/19/30 交付素材和版本表；肖像、音乐、客户标识和付费使用范围需具名确认。DoD：母版、渠道版、授权、字幕、alt 文本和投放规格齐全。

## 12. 社交媒体运营

**使命与职责**：经营公众号、小红书、抖音、LinkedIn、X、TikTok 等账号；完成平台适配、发布、互动、评论与私信承接、账号健康和内容节奏；维护平台 Overlay。

**KPI**
- 结果：合格互动人数、有效问题 / 对话、社交到访后的激活或留资；目标受众的持续关注与回访。
- 过程：响应 SLA、发布计划完成率、评论处理覆盖率、平台资产健康检查完成率。
- 护栏：删除 / 限流 / 举报、拉黑与负反馈、过度发布、账号异常。粉丝和曝光不是业务结果的替代品。

**标准 SOP**：①确认账号授权、受众、平台规则和目标 → ②接收内容母版并完成平台化改写 → ③预览、事实 / 权利检查与执行审批 → ④按授权方式发布并回读可见性 → ⑤处理评论、私信、问题和危机升级 → ⑥记录合格对话及后续承接 → ⑦复盘平台规则、内容形式与互动质量。

**核心产出 / 模板**：社媒月 / 周运营方案、发布日历、互动处置表；使用 **T07**。

**交接 / 人审 / DoD**：向 15/18/26/34/40 交接有上下文的对话；所有发布走既有执行门禁，危机和敏感回复升级。DoD：真实回执、可见性、互动 Owner、下一动作和停止条件齐全。

## 13. KOL / KOC 与达人营销

**使命与职责**：招募、筛选和管理达人 / 博主 / 创作者；设计合作主题、报价、权益、披露、素材授权与结算；维护 MCN 和创作者关系；评估真实影响而非表面粉丝量。

**KPI**
- 结果：合作带来的激活用户、合格线索或净收入；有效合作达人率；每个合格结果成本；二次合作率。
- 过程：brief 一次通过率、准时上线率、素材交付完整率、结算周期。
- 护栏：虚假互动、披露缺失、品牌安全、授权超期、返佣 / 欺诈、受众错配。

**标准 SOP**：①定义合作目标、受众、报价与权利边界 → ②建候选名单并审查历史内容、受众和异常互动 → ③沟通主题、交付、披露、修改和排他条款 → ④签署合作 brief 并审核素材 → ⑤授权发布、追踪链接 / 代码和舆情 → ⑥核验合格结果与结算 → ⑦评级、续约或停用并更新达人库。

**核心产出 / 模板**：达人合作方案、筛选评分卡、创作者 brief、授权 / 结算表；使用 **T08**。

**交接 / 人审 / DoD**：向 11/12/17 提供批准素材，向 29/35/38 提供承接信息；合同、付款、排他和客户数据使用必须人审。DoD：发布链接、素材版本、披露、授权期限、结果口径和结算证据可追踪。

## 14. 搜索与自然流量（SEO / SEM / ASO / AEO / GEO）

**使命与职责**：管理技术可发现性、搜索内容、关键词 / 问题覆盖、站外引用、应用商店和 AI 答案可见性；区分品牌与非品牌需求；保持搜索资产健康。SEM 的付费执行与 17 协作。

**KPI**
- 结果：非品牌自然合格访问及其激活 / 线索；有效页面覆盖；应用商店页转化；在预定义问题集中的品牌引用 / 提及变化。
- 过程：技术问题修复周期、有效索引率、内容更新率、ASO 版本迭代周期。
- 护栏：抓取 / 索引异常、关键词自相蚕食、垃圾外链、错误答案引用、商店违规。采样到的 AI 引用不能外推为全部用户可见性。

**标准 SOP**：①确定业务问题集、目标页面和测量样本 → ②审计技术、内容、商店和现有引用 → ③建立问题—页面—行动映射与优先级 → ④修复技术并生产 / 更新内容 → ⑤验收结构化信息、内部链接、事实与平台规则 → ⑥发布并观察索引、排名、引用和后续行为 → ⑦处理衰退、蚕食和错误引用。

**核心产出 / 模板**：搜索自然增长方案、技术审计、问题—页面地图、AEO / GEO 监测表；使用 **T09**。

**交接 / 人审 / DoD**：向 09/10/24/25/46 提供页面与问题需求；技术改动和大规模页面上线需产品 / 工程审批。DoD：每个优化项有页面、问题、预期行为、验证方法和回滚方式。

## 15. 社区与口碑传播

**使命与职责**：经营论坛、品牌社区、粉丝与用户贡献；促进答疑、评价、用户证言和案例传播；管理社区规则、主持、品牌大使和口碑风险。

**KPI**
- 结果：有贡献的活跃成员、被解决问题数、回答后被采用率、社区成员留存 / 激活、合格推荐。
- 过程：首响时间、 unanswered backlog、主持人处理 SLA、社区活动完成率。
- 护栏： toxicity / 骚扰、垃圾内容、未处理安全议题、刷评价、少数贡献者过度集中。

**标准 SOP**：①定义社区目的、成员任务和规则 → ②设计板块、角色、主持与升级路径 → ③冷启动核心成员和高价值内容 → ④日常答疑、认可贡献和组织活动 → ⑤处理冲突、违规和安全升级 → ⑥筛选经授权的评价 / 案例并交接 → ⑦复盘成员贡献与社区健康。

**核心产出 / 模板**：社区运营方案、规则与主持手册、口碑 / 案例候选表；使用 **T07 / T23**。

**交接 / 人审 / DoD**：向 09/39/40/46 交接内容、案例和支持问题；公开评价、客户 logo 和用户故事必须取得授权。DoD：问题有归宿，贡献有认可，敏感事项有升级记录，社区结果不拿发帖总量替代。

# C. 增长、流量与获客运营

## 16. 用户增长

**使命与职责**：对获客—激活—留存—变现的整漏斗提出假设并编排实验；协调渠道、产品、内容和数据；管理增长模型、边际成本与增长质量，而非只负责拉新。

**KPI**
- 结果：新增激活 / 付费 / 留存主体、增长带来的净收入、增量 CAC 与回收期；核心漏斗分阶段变化。
- 过程：有效实验完成数、从假设到结论周期、跨团队阻塞解除时间。
- 护栏：新增用户留存质量、投诉 / 退订、边际成本、激励套利、渠道集中度。同期增长不能直接宣称为实验增量。

**标准 SOP**：①明确唯一业务瓶颈和合格主体 → ②建立漏斗基线、约束与可检验假设 → ③按影响 / 证据 / 成本排序实验 → ④预注册指标、样本、护栏和停止条件 → ⑤协调交付并授权执行 → ⑥核验结果、下游质量和异常 → ⑦决定推广 / 迭代 / 停止并更新增长模型。

**核心产出 / 模板**：增长诊断与实验组合、实验卡、增长模型；使用 **T10 / T28**。

**交接 / 人审 / DoD**：向 17/18/24/25/34/44 分发明确任务并收回复核结果；预算、产品变更和激励规则需审批。DoD：假设、机制、口径、结果和下一决策完整，缺样本只能写不确定。

## 17. 付费广告与效果营销

**使命与职责**：制定媒体与账户结构、预算、出价、受众、素材和落地页协同；管理 Paid Search / Social、信息流、程序化和账户健康；评估边际与增量效果。

**KPI**
- 结果：合格转化数、CPA / CAC、贡献利润口径 ROAS、合格 pipeline 或净收入；边际转化成本。
- 过程：预算执行偏差、素材迭代周期、搜索词 /  placements 审核覆盖率。
- 护栏：超支、频次、拒登、低质线索、品牌 / 隐私合规、归因重复。平台自报 ROAS 不等于增量回报。

**标准 SOP**：①确认目标事件、预算、利润和归因边界 → ②审计账户、历史搜索词、受众和素材 → ③设计账户 / campaign / 实验结构与承接页 → ④核验转化追踪、素材、权利和花费审批 → ⑤小预算启动并监测异常 → ⑥按预先规则调预算、出价、受众与素材 → ⑦结算、复盘并回填真实质量。

**核心产出 / 模板**：投放方案、账户结构表、预算与素材测试表；使用 **T11**。

**交接 / 人审 / DoD**：向 11/25/18/44 提供 brief 和实际结果；充值、加预算、新受众和敏感定向必须人审。DoD：实际花费、平台回执、转化来源、异常和未决归因清楚。

## 18. B2B 需求增长（Demand Gen / Lead Gen / ABM）

**使命与职责**：围绕已确认 ICP 建目标账户和人群覆盖；组合内容、活动、广告、邮件与 ABM；培育潜客、识别购买信号并交付销售可接受的商机；管理 pipeline 来源质量。

**KPI**
- 结果：销售接受商机数、目标账户合格互动、创建 / 推进 pipeline、成交收入与周期；会议实际到场率。

# D. 激活、转化、销售与交易运营

## 24. 产品增长与激活

**使命与职责**：定义并提升新手价值实现、Onboarding、试用转付费、功能采用和 PLG 承接；识别激活断点并协调产品、内容、生命周期和客服。

**标准 SOP**：①与业务确认合格主体和激活事件 → ②重建新手旅程并定位时间 / 行为断点 → ③提出产品、内容或触达处方 → ④定义样本、护栏、开发和验收条件 → ⑤实验 / 发布并监测新老用户 → ⑥核验激活及后续持续使用 → ⑦固化或回滚 onboarding 规则。

**交接 / 人审 / DoD**：向 25/34/35/40/44 提供旅程与事件定义；产品变更、付费承诺和触达需相应审批。DoD：激活定义、事件来源、版本、用户群和后续质量可复核。

## 25. 转化率优化（CRO）

**使命与职责**：优化官网、落地页、表单、支付和关键路径；建立研究—假设—设计—实验—读数—发布流程；保证实验有效和下游质量。

**KPI**
- 结果：指定阶段 CVR、每合格访问者的激活 / 收入、实验相对提升及不确定性；成功后业务质量。
- 过程：有效实验比例、实验周期、复现率、实验 backlog 质量。
- 护栏：SRM、样本不足、peeking、多重比较、页面性能、下游低质转化和退款。未达样本不得写成“提升已证实”。

**标准 SOP**：①锁定单一路径与业务阶段 → ②核对基线、埋点、分群和技术问题 → ③形成有机制的假设与设计方案 → ④预注册主指标、样本、护栏和停止规则 → ⑤QA 后运行实验 → ⑥检查 SRM、数据和下游质量 → ⑦由人决定发布 / 迭代 / 停止并记录限制。

**核心产出 / 模板**：CRO 方案、实验卡、QA / 读数报告；使用 **T15 / T28**。

**交接 / 人审 / DoD**：向 11/16/17/24/44 提供页面和实验结论；线上变更和支付路径修改人审。DoD：假设、版本、流量分配、数据质量、结果与决策完整。

## 26. 销售线索开发（SDR / BDR）

- 过程：speed-to-lead、名单研究完整率、交接一次通过率、跟进 SLA。
- 护栏：退信、退订 / 投诉、AE 拒收、错误身份、过度触达。邮件 / 电话量不是核心结果。

**标准 SOP**：①接收已确认 ICP、名单和接触资格 → ②核验账户、角色、触发和数据许可 → ③形成个性化问题与消息 → ④审批后分渠道触达并处理回应 → ⑤按统一资格标准确认问题、角色、时机和下一步 → ⑥确保会议并交付上下文 → ⑦回收 AE 拒收 / 推进结果并修订名单规则。

## 27. 直接销售与客户成交（AE）

**使命与职责**：负责发现、资格、方案、商业论证、谈判、采购、合同与成交；维护机会阶段、下一步、预测和丢单原因；避免过度承诺并确保可交付。

- 护栏：折扣、退款 / 早期流失、错误承诺、回款风险、预测偏差。合同额与到账分列。

**标准 SOP**：①验收 SDR / 市场交接或自建机会 → ②完成发现、购买组、流程与资格 → ③联合售前 / 交付确认价值和方案 → ④形成商业论证、报价与互进行动计划 → ⑤处理异议、采购、法务和审批 → ⑥签约 / 到账并记录准确状态 → ⑦向 CSM 交接承诺并复盘赢单 / 丢单。

**核心产出 / 模板**：账户 / 机会计划、发现记录、商业论证、报价与成交交接；使用 **T16 / T31**。

**交接 / 人审 / DoD**：向 28/32/38/42 交接范围、承诺和预测；报价、折扣、合同和公开客户引用需授权。DoD：机会证据、决策链、下一承诺、金额口径和交付边界可追踪。

## 28. 售前与方案支持

**使命与职责**：负责技术发现、方案架构、Demo、POC、投标、安全与集成评估；定义技术成功标准、范围、资源和风险；防止销售承诺不可交付。

**交接 / 人审 / DoD**：向 27/38/45 交接技术与集成约束；访问客户环境、安全声明和定制承诺人审。DoD：范围、非目标、成功标准、双方责任、证据和未决风险签字。

## 30. 直播与内容电商

**交接 / 人审 / DoD**：向 18/26/27/38/43/45 交接销售事实和规则；佣金、区域调整、批量阶段 / 金额修改人审。DoD：字段定义、数据来源、调整记录、争议与审批可追踪。

## 43. 收入运营（RevOps）

**使命与职责**：统一营销—销售—客户成功的收入漏斗、生命周期、预测、系统集成与经营节奏；管理跨部门数据定义和收入分析，而不是简单合并报表。

**KPI**
- 结果：分阶段漏斗推进、NRR / GRR、预测准确、CAC payback / 收入质量（与 Verovo / 财务口径对齐）、收入系统对账覆盖。
- 过程：指标字典覆盖率、跨部门 SLA、数据问题关闭周期、经营会议行动完成率。
- 护栏：定义漂移、未分配 / 重复收入、跨系统差异、身份错并、未经证实因果归因。

**标准 SOP**：①确认客户生命周期、主体和收入口径 → ②映射营销 / 销售 / CS 阶段、系统与 Owner → ③建立指标字典、身份和收入对账 → ④形成漏斗、预测和异常视图 → ⑤组织跨部门经营复盘并指定行动 → ⑥跟踪动作与结果 → ⑦经审批变更流程 / 口径并保留历史兼容。

**核心产出 / 模板**：RevOps 收入架构、生命周期 / 指标字典、经营复盘与对账表；使用 **T27**。

**交接 / 人审 / DoD**：向 16/18/27/38/41/42/44/45 分发统一定义；生命周期、历史重述和收入口径变更需多部门签收。DoD：同一主体、同一窗口、同一版本可对账，差异不被隐藏。

## 44. 增长数据与实验

**使命与职责**：维护行为分析、渠道归因、漏斗、CAC / LTV 输入和实验方法；保证数据质量、样本、复现与推断边界；把分析转为具体决策而非综合评分。

**KPI**
- 结果：支持的实际决策数、有效实验比例、决策周期、可复现分析覆盖、实验后真实采用 / 收入变化。
- 过程：数据新鲜度、分析复现率、实验 QA 通过率、指标请求 SLA。
- 护栏：SRM、peeking、多重比较、样本不足、数据缺失、隐私越权、把时间相关写成因果。

**标准 SOP**：①把业务问题写成可检验问题 → ②确认主体、事件、窗口、数据源和质量 → ③预注册假设、主指标、护栏和分析计划 → ④执行实验 / 准实验或描述分析 → ⑤检查样本、异常、敏感性和替代解释 → ⑥由业务 Owner 决定动作 → ⑦归档代码 / 数据 / 结论并跟踪决策结果。

**核心产出 / 模板**：分析计划、实验卡、数据质量报告、决策备忘录；使用 **T28**。

**交接 / 人审 / DoD**：向 16/17/24/25/34/43 提供可复核结论；敏感数据、生产实验和收入因果表述人审。DoD：查询 / 版本、样本、限制、结果和实际决策可重跑。

## 45. GTM 工程与自动化

**使命与职责**：实现潜客识别、授权数据富集、CRM / 营销 / 销售系统集成、触达准备和自动化工作流；管理 API、队列、异常、权限、日志和人工接管；不是绕平台限制的群发工程。

**KPI**
- 结果：端到端自动化成功率、合格数据接受率、处理时延、经抽检验证的人工时间节省、业务任务完成。
- 过程：同步新鲜度、异常恢复时间、运行覆盖率、可追溯运行比例。
- 护栏：重复 / 错误写入、未知结果、凭据事件、平台违规、自动化偏差、过度富集。调用成功不等于业务任务完成。

**标准 SOP**：①确认业务任务、系统权限和数据合法性 → ②绘制输入—转换—写入—回读及异常路径 → ③定义 idempotency、限额、抑制和人工接管 → ④在沙盒 / 小样本测试并核对写回 → ⑤审批部署并绑定账号 / 工作区 → ⑥监测运行、异常、成本和数据质量 → ⑦人工裁决未知结果并版本化修复。

**核心产出 / 模板**：GTM 自动化设计、字段映射、运行 / 异常手册、权限清单；使用 **T29**。

**交接 / 人审 / DoD**：向 18/26/35/41/42/43 提供可运维服务；生产写入、敏感数据、凭据和外部平台自动化人审。DoD：授权、输入输出、幂等、日志、回滚、异常与 Owner 齐全，实际写入仍走统一执行路径。

## 46. 开发者与生态运营（DevRel）

**使命与职责**：负责 Developer Marketing / Advocacy、技术内容、文档、示例、开源社区、开发者活动、生态伙伴和 API Adoption；让开发者完成真实技术任务并持续采用。

**KPI**
- 结果：首次成功 API / 示例运行的开发者数与时间、持续采用、有效技术内容任务完成、活跃贡献者和生态集成。
- 过程：文档 / 示例新鲜度、问题响应 SLA、技术内容复现通过率、活动后有效项目跟进。
- 护栏：坏样例 / 坏文档、未解决问题、社区骚扰、虚假下载 / Star、无授权代码 / 数据。Star / 下载不等于激活或采用。

**标准 SOP**：①定义开发者任务、目标项目和成功事件 → ②审计文档、SDK、示例、issue 和生态路径 → ③设计技术内容、示例、活动或伙伴计划 → ④真实复现并由技术 Owner 验收 → ⑤授权发布 / 活动并处理讨论 → ⑥核验首次成功、持续使用和贡献 → ⑦修复文档 / 示例并回流产品与内容规则。

**核心产出 / 模板**：DevRel 计划、技术教程 / 示例 brief、开发者 Journey、生态项目表；使用 **T30**。

**交接 / 人审 / DoD**：向 09/12/15/19/24/39/40 提供技术资产和真实问题；代码合并、安全议题、公开发布和伙伴承诺人审。DoD：复现命令、环境、预期结果、实际回执、技术限制和后续采用事件完整。
