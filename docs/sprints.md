# 冲刺（Sprint）

> 代码：`core/sprint.py` · CLI：`mkt sprint plan` · MCP：`mkt_sprint_plan`
> 状态：本地实现与测试通过；是排期与约束检查，不是结果保证。

## 为什么要有冲刺

六周计划回答「怎么稳稳地做」；冲刺回答「如果只有 3 天，先做什么、同时做什么、
什么必须砍掉」。两者不是压缩关系，是两套打法：

| | 六周计划 | 3 天冲刺 |
|---|---|---|
| 节奏 | 每周一波，留跟进 | 每 8 小时一个检查点 |
| 内容 | 按平台做多篇 | **一个资产，多个表面** |
| 受众 | 自己养 + 社区 | **借场优先**：先去人群已经在的地方 |
| 触达 | 15 条，分散 | **30 条，压到 3 天** |
| 判据 | 4 周判定 | 72 小时三选一 |

## 怎么用

```bash
# 已有目标选择
python3 mkt.py sprint plan --facts data/verovo-finops/facts.json \
  --selection data/verovo-finops/goal-selection.json \
  --days 3 --start 2026-11-05

# 也可以现场指定目标和平台
python3 mkt.py sprint plan --facts data/verovo-finops/facts.json \
  --goal awareness.stars --secondary adoption.real_data \
  --platforms github,hackernews,reddit --days 3
```

输出：

- **每天追什么**：把目标按「前重后轻」拆到每天；辅目标默认滞后 1 天（先有触达，再有数据）；
- **并行工作流**：资产 / 发射 / 放大 / 直连 / 承接 / 判定；
- **小时级排期**：每条带时间、工作流、做什么、谁做、验收物；
- **加速杠杆**：借场、一鱼多吃、并行直连、时限稀缺、存量关系、公开构建；
- **到点就换**：2 小时 / 24 小时 / 48 小时三个检查点；
- **容量校验**：平台日限与人工小时，超了标红；
- **红线**：不买星、不群发、不伪造、不承诺；
- **72 小时判定**：两个都达成 / 只达成一个 / 都没动。

## 时间与时区

默认发射时间 `21:00`（北京时间），对应美东冬令时 08:00——HN 的工作日早高峰。
用 `--launch-hour` 改；用 `--start` 改开始日期；用 `--hours-per-day` 改人工预算。

## 六个杠杆

| 杠杆 | 怎么做 | 主要风险 |
|---|---|---|
| 借场 | 去人群已经在的地方发 | 版规；先读规则、先答问题 |
| 一鱼多吃 | 一份资产拆成 HN/Reddit/X/LinkedIn/清单 | 重复感；每个表面换开头 |
| 并行直连 | 30 条具名私信压到 3 天 | 像群发；每条引用对方原话 |
| 时限稀缺 | 前 5 个给数据的人做免费 24h 样本 | 白嫖；先给范围再要数据 |
| 存量关系 | 已说过话的人 + 老客户先看/转 | 消耗关系；只请一次 |
| 公开构建 | 每天发真实数字 | 自嗨；只发数字和教训 |

## 容量校验怎么读

`LIMITS` 是「不把账号打坏」的保守上限，不是平台上限：

- HN：1 帖/天、10 评论/天；
- Reddit：2 帖/天、10 评论/天；
- X：3 帖/天、20 回复/天；
- LinkedIn：1 帖/天、15 邀请/天、20 消息/天；
- GitHub：3 issue/天、10 评论/天。

超限时 `capacity.over_limit` 会列出来；冲刺计划不会替你降量，只告诉你「这么打会出事」。

## 边界

- 3 天冲刺是**信号测试**，不是市场验证；目标达成只说明这 3 天的资产、表面和话术有效。
- 不证明需求、付费、可复购或可规模化；72 小时后要复现一次，再谈加量。
- 不买星、不互投、不进投票群、不群发、不伪造数据；这些不是「加速」，是把账号和信誉一次烧掉。
- 冲刺计划是排期，不是承诺；平台删帖、限流、审核都可能让计划失效，按「到点就换」处理。
