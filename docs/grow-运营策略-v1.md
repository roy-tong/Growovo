# Growovo 增长运营策略 v1：KOC 优先的「找对的人 → 说对的话 → 每天改一点」

- 日期：2026-11-14
- 适用：早期增长（粉丝 < 5k、没有投放预算、没有成熟内容团队）
- 代码：`core/grow_fit.py`（账号/帖子契合度）、`core/grow_content.py`（内容公式与闸门）、
  `core/grow_learning.py`（指标归因与次日建议）、`core/grow_targets.py`（只读发现）
- 命令：`mkt grow prospects / formulas / stage / metrics / learn / review / decide`

---

## 0. 一句话策略

**先把产能压在垂直 KOC 身上，用「同行补充」式回复换真实对话；用自己的帖子证明值得关注；
每天用自己帖子的公开指标做小步调整，而不是拍脑袋加量。**

不追头部大号，不买粉，不互关，不群发，不用互赞群。

---

## 1. 找谁：KOC 优先，而不是「粉丝最多」或「人最多」

### 1.1 为什么是 KOC

- 粉丝 **1k–50k** 的垂直账号，通常没有专业商业化团队运营，表达更像真人；
- 他们的粉丝对「推荐」更信任，一条认真回复带来的主页访问，质量高于大号下的淹没式回复；
- 头部大号（>300k）回复几乎不会被看到，早期把产能花在那里是浪费；
- 大量普通用户（<200 粉）对话意愿高，但短期不带来扩散，适合少量维护、不适合当主战场。

### 1.2 账号分档（代码里写死，可解释）

| 档位 | 粉丝量 | 策略 |
|---|---|---|
| nano | <200 | 可少量对话，不做主战场 |
| micro | 200–1k | 对话意愿高，扩散有限 |
| **KOC** | **1k–50k** | **早期主战场，优先回复与维护** |
| mid | 50k–300k | 能带量但易被淹没，选择性互动 |
| macro | >300k | 只读不追，不投入产能 |

### 1.3 两层评分

1. **帖子契合度**（0–100）：产品关键词命中、求助/讨论信号、是否提问、互动量级、新鲜度；
   命中越多、越像「正在解决这个问题」越高分。
2. **账号契合度**：KOC 档位、bio 与近期内容是否垂直、是否营销号、粉丝量级；
   最终候选按「是否 KOC → KOC 分 → 帖子分 → 相关帖数」排序。

评分不是自动决定发什么，而是把有限产能排到最可能产生对话的人身上。

### 1.4 每天怎么用

```bash
# 1) 只读发现账号：不写 query 时按产品关键词自动生成搜索词
mkt grow prospects g1 --koc-only --top 8 --max-age-hours 72

# 2) 选 A/B 级账号的最佳帖子；stage 可自动读原帖、校验公式
mkt grow formulas g1
mkt grow stage g1 --from drafts.json --date 2026-11-15 \
  --resolve-target --strict

# 3) 看名单：谁已触达、谁还没动，避免每天重复打扰同一批人
mkt grow koc g1
```

两段式筛选：先按帖子分挑作者（不花主页读取配额），再读作者主页打分；
已触达账号默认排除，`--include-engaged` 才包含。KOC 在当前关键词下通常很少，
`--koc-only` 没结果时会列出「接近 KOC」的账号和原因，而不是给一个空列表。

候选清单落 `data/grow/<id>/prospects/<date>.json`；`targets` 命令只出帖子清单，
`prospects` 会额外读作者主页（bio/粉丝/近期内容），只读，不关注不点赞。

## 2. 说什么：三层内容，回复不谈产品

### 2.1 三层结构

| 层 | 做什么 | 在哪 | 目标 |
|---|---|---|---|
| **发现层**（reply） | 在 KOC 帖子下提供增量，换对话和主页访问 | 别人的帖子 | 被看见、被回复 |
| **证明层**（post） | 原创拆解/清单/案例，证明「持续解决同一类问题」 | 自己的主页 | 点进来的人愿意关注 |
| **承接层**（profile） | bio、置顶、近期内容一致 | 主页 | 关注转化 |

关键顺序：**先同意具体观点 → 再补一个他没说到的细节/数字 → 最后用一个真问题接下去**。
吸引主页访问靠「这条回复有信息增量」，不靠「来我主页」；CTA 只放在自己的帖子里。

### 2.2 回复公式（三选一）

| 公式 | 节奏 | 适合 |
|---|---|---|
| `reply.agree_extend_ask` | 同意 → 补充 → 追问 | 对方描述真实问题，你有同类经验 |
| `reply.contrast_boundary` | 同意 → 反向边界 → 追问 | 对方结论大体对，但漏了条件/代价 |
| `reply.experience_number` | 经验 → 具体数字 → 追问 | 你有真实数字、流程或失败教训 |
| `reply.koc_peer` | 同行补充 → 追问 | 垂直 KOC 的帖子：不恭维、不推销 |

### 2.3 原创公式（三选一）

| 公式 | 节奏 | 用途 |
|---|---|---|
| `post.teardown` | 钩子 → 背景 → 方法 → 证据 → 边界 → 邀请 | 展示专业深度 |
| `post.checklist` | 钩子 → 清单 → 证据 → 邀请 | 被收藏、被转发 |
| `post.case` | 钩子 → 处境 → 动作 → 结果 → 教训 | 建立信任 |

### 2.4 配比（早期）

- 回复 85%：每天约 1–3 条，全部针对具体帖子；
- 原创 15%：每周 1–2 条，做主页门面；
- 同一句话不重复用；同一个 KOC 先认真回一次，不连续刷。

### 2.5 写作闸门（`stage` 时自动跑）

- 回复必须接上对方帖子的具体内容（缺 `target_text` 会提示）；
- 必须有增量（数字/经验/做法），不能只表态；
- 结尾要有真问题；空泛夸（great post/说得好）直接扣分；
- 回复里禁止链接、禁止产品名、禁止关注/私信 CTA；
- 长度 60–280；营销引流词扣分；
- 输出 0–100 结构分 + 问题清单；低分照发也可能有效，但系统会提示先按公式重写。

**边界**：结构分是启发式，不预测流量；平台算法、受众状态、时机都影响结果。

## 3. 每天改一点：复盘 → 次日动作

### 3.1 采集

```bash
mkt grow metrics g1 --days 7 --limit 20
```

- 只读自己已发布帖子的公开指标：查看、喜欢、回复、转帖；
- 帖子 URL 由 tick 在发送后自动解析（找到「我们自己的那条」，而不是目标帖）；
  补跑历史帖子用 `mkt grow metrics g1 --resolve`；
- 指标落 `data/grow/<id>/post_metrics.jsonl`，重复采集按 URL 去重。

### 3.2 归因

```bash
mkt grow learn g1
```

按 **公式 / 时间窗 / 作者档位** 分组，给样本数、查看中位、回复中位、回复率中位。
**每组样本 <3 时不调参**，只提示继续采集。

### 3.3 次日优化

```bash
mkt grow review g1 --days 7      # 含「今日不足与明天动作」
mkt grow decide g1 --action optimize --dry-run   # 先看提案
mkt grow decide g1 --action optimize --note "按学习调整"
```

- `learn` 产出的提案带 rollback；`decide optimize` 应用时只改执行参数
  （公式配比、KOC 触达占比、周计划量），不改策略选择（换渠道/换目标只出提案）；
- 若 KOC 组回复率显著高于非 KOC，会提案把 KOC 触达目标从 60% 提到 70%；
- 供给不足时优先对齐供给，不为了完成率硬发。

### 3.4 每日复盘的固定问题

1. 今天发了几条 / 计划几条？差在哪（供给、窗口、失败）？
2. 读数有没有拿到？没有先修读数，不用残缺数据下结论。
3. 今天触达的人里 KOC 占多少？低于目标就先补 KOC 名单。
4. 暂存内容的结构分均值多少？低于 60 先按公式重写。
5. 今天有没有记录决定？没有就用 `decide` 明确继续或优化。

## 4. 不该做的事（写进产品红线）

- 不买粉、不互关、不参加互赞群、不做 engagement pod；
- 不群发、不复制同一句回复、不在回复里放链接或产品名；
- 真实发送之间保留 60–120 秒随机间隔，不连发；窗口外不发；
- 超过 2 天没发出去的内容不补发（过期回复会显得突兀），换新内容；
- 不追头部大号；不因为「有候选」就直接发；
- 不把查看/喜欢/粉丝当业务转化；不在样本不足时改配比；
- 不绕过平台风控（验证码、指纹、代理池）。

## 5. 一周的样子（示例）

| 天 | 动作 |
|---|---|
| 周一 | `prospects` 找 8 个 KOC → 写 3 条回复 → `stage` → 自动发送 |
| 周二 | 同上；`metrics` 采集昨天帖子；`review` 看缺口 |
| 周三 | 写 1 条原创拆解（证明层）；回复 2 条 |
| 周四 | `learn` 看公式分组；`decide optimize` 小步调权 |
| 周五 | 回复 3 条；`review` 检查 KOC 占比与读数覆盖 |
| 周末 | 不强制发；整理下周 KOC 名单与选题 |

早期目标不是「发得多」，而是**建立 20–50 个真实 KOC 关系 + 主页有 3 条能证明能力的帖子**。

---

## 6. 如何判断策略有效（不夸大）

- 过程指标：KOC 触达数、回复率（有人回你）、主页访问（若平台给）、关注增量；
- 结果指标：关注者净增、来自目标人群的互动；
- 证据边界：公开指标是相关不是因果；样本 <3 不下结论；不承诺平台流量。
- 停止规则：连续 2 周 KOC 回复率无改善 → 换选题/换人群，不加量；
  出现限流/警告 → 停自动化，先修内容与账号。
