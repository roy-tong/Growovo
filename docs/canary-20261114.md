## 读数校准（连续 7 天）

每天人在 X 后台手读一次粉丝数，然后：

```bash
python3 mkt.py grow tick canary          # 当天自动读数
python3 mkt.py grow calibrate canary --followers <手读数> --by "$USER" --note "手读 profile"
```

- 一致 → `match=true`；7 次连续一致后自动把 `measurement.verification` 升级为 `PROVEN`。
- 不一致 → 加 `--mismatch`，连续计数归零，先检查解析器/UI 变化，不要放量。
- 曝光指标：账号 ≥50 关注者后 X 才给明细；在此之前结果单如实写「取不到」，不是 0。

不想每天手动跑 tick 时，双击仓库根目录的 `canary-tick.command`，它每 30 分钟 tick 一次。

## 环境问题与处理

1. **调试 Chrome cookie 为空**：重启 `launch.command` 后会话恢复（cookie DB 有 auth_token，但首次连接读到 0 条）。若再次出现，先重启调试 Chrome 再试。
2. **Playwright 1.60 + Chrome 157 不兼容**：连接时报 `Browser.setDownloadBehavior: Browser context management is not supported`。初始调试曾对本地驱动打补丁；0.14.0 现在优先使用 Playwright 原生 `no_defaults` 连接选项，保持已有浏览器上下文，不再要求该本地补丁。旧版 Playwright 不支持该选项时仍走原连接方式。
3. **launchd 被文档目录保护拦住**：`launchctl` 里的 python 读不到 Documents 下的 `mkt.py`（Operation not permitted）。两条路：
   - 系统设置 → 隐私与安全 → 完全磁盘访问权限 → 加入 `/Library/Developer/CommandLineTools/usr/bin/python3`，再 `mkt grow install canary --load`；
   - 或先用 `canary-tick.command` 前台常驻。
4. **读数解析修复**：中文 UI 把 Followers 译作「关注者」（不是「粉丝」），且分析页应为 `/i/account_analytics` 而不是 `/analytics`（后者会被当成用户名）。已修并加测试。
