# V2EX

> 一句话：中文独立开发者/程序员的高浓度社区——规则严、节点自治，「分享创造」是发布作品的正门，广告与软文是死路。 · 研究日期：2026-11-03 · 官方口径：FAQ/社区规则页已核（链接） · **自家实测：无**

## 1. 这里是什么地方
**谁在这里**：程序员、独立开发者、技术从业者；发帖质量高、批评直接、匿名文化。
**来干什么**：技术讨论、找工作、看别人做了什么（「分享创造」）、吐槽。
**GTM 角色**：**发现 + 同行反馈**。中文 devtool/独立产品的第一发布站；用户是同行，反馈专业且不留情面。

## 2. 内容怎么被看见
- **分发**：节点（node）组织 + 首页时间流聚合；无算法推荐。**节点选对=被对的人看到**。
- 「分享创造」（/go/create）是最活跃节点之一：独立开发者分享作品（Mac 工具、AI 产品等），常附邀请码/会员求反馈——**社区共识：分享自己的作品（含商业产品）在此允许且受欢迎**；但刷屏、发多节点、伪装普通帖的软广会被处理（[社区讨论](https://v2ex.com/t/1081342)、[知乎申诉讨论](https://www.zhihu.com/question/53494780)，**社区共识+官方规则**）。
- **曝光持续**：帖子 1–2 天沉底；搜索/收藏长尾弱。
- **新手**：注册即可发（部分节点有门槛），但新号无历史直接发推广帖是风险信号。

## 3. 官方规矩
- **官方规则页**：[v2ex.com/help/faq](https://v2ex.com/help/faq) 与 [v2ex.com/help/community-rules](https://v2ex.com/help/community-rules)（**已核存在**）：正确节点发帖；推广内容发到「分享创造」等专门节点；禁止广告性质主题、营销号、批量注册。
- **处罚**：冻结（多数"被封"实为冻结，可申诉解冻，联系管理员 Livid 或站内反馈）、封 IP、降权（帖子不再出现在首页）。
- **加重情节**：被封后注册新号逃避——坐实违规。

## 4. 真实打法（开发者工具/独立产品主场景）
1. **第一步**：账号先参与两周技术讨论（攒"居民"身份）。
2. **发布**：「分享创造」节点，标题=产品名+一句话价值；正文=解决什么问题/技术栈/免费额度或邀请码（V2EX 文化：给社区福利）；诚实写局限。
3. **节奏**：一个产品发一次；重大更新再发。
4. **见效**：发布当天~48 小时是全部窗口；量级=精准同行反馈+早期用户（几十到几百 UV 级 [**推测，无对照数据**]）。
5. **失败的样子**：发错节点（如发到「随想」）、标题党、正文无干货只有链接、被问技术细节答不上。

## 5. 死路
1. 综合节点发广告链接（明令禁止）。2. 伪装普通用户的软广（社区鉴别力极强）。3. 多节点重复发帖。4. 被处理后换号（加重）。5. 把 V2EX 当长期运营阵地（它是发布+反馈站，不是内容平台）。

## 6. 这里的人怎么说话
克制、技术细节导向、反感营销词；"利益相关"披露是礼仪（"作者，利益相关"开头很常见）。忌讳：感叹号、表情包、形容词堆砌。好开头（[模式还原]）："做了一个 XX，解决我自己的 XX 问题。技术栈 boring 但实用。送 100 个邀请码。" / "利益相关：开发者。这个产品的坑我都在文末列了。"

## 7. 账号与节奏
新号可发但建议先有互动历史；发布型平台无日常节奏要求；时段工作日早/午（开发者摸鱼）。[**未核实**] 资产：账号信誉、邀请码发放记录。

## 8. 风控与踩线
识别：人工管理（Livid）+ 众包举报（社区自治）；批量注册检测。信号：帖子被移出首页/节点、账号冻结。处理：申诉解冻（FAQ 渠道）；**更糟**：换号逃避。

## 9. 怎么衡量有用
能拿到：帖内回复、UV（自建短链）。拿不到：平台数据（V2EX 无创作者后台）。被问到：回复里"求邀请码/怎么收费"。误读：回复少=失败（V2EX 回复门槛高，短链点击才是口径）。

## 10. 适不适合
适合：中文 devtool、独立产品发布、找首批同行用户。不适合：非技术产品、海外产品、需要长期流量的（长尾弱）。搭配：V2EX 发布（同行冷启动）→ GitHub 仓库（承接）→ 掘金长文（沉淀）。
