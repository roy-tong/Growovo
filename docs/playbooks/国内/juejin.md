# 掘金

> 一句话：中文技术内容第一社区——先审核后推荐、原创硬门槛、对"有个人洞察的技术文"友好，对营销内容"原则上不支持但不一刀切"。 · 研究日期：2026-11-03 · 官方口径：多篇官方帖/小册已核 · **自家实测：无**

## 1. 这里是什么地方

**谁在这里**：中文开发者为主（前端/后端/AI 方向密度最高），刷首页找技术解法和行业动态，学习心态强、对水文耐受度极低。

**他们来干什么**：搜报错解法、选型对比、新特性实践；沸点区有轻量的行业闲聊。

**在 GTM 里的角色**：**信任 + 长尾**（开发者工具在国内的主阵地之一）。和知乎的差别：知乎答"决策问题"，掘金发"实践长文"；掘金读者就是开发者本人——对 devtool 来说读者≈用户。

## 2. 内容怎么被看见

- **分发靠什么**：首页推荐（编辑+算法双轨）+ 搜索 + 关注。**每篇文章先过审核，通过后才能被搜索和推荐**；上了首页后再编辑，可能无法再次上首页（[掘金审核机制讨论](https://juejin.cn/post/6979141039294513166)，**作者实测**）。
- **什么内容会被推**：官方推荐标准——对他人有启发性、**必须原创或本人翻译**、行文排版优雅、与开发相关的技术内容（[《如何使用掘金社区》官方小册](https://juejin.cn/book/m/6844733795329900551/section/6876001660431400967)，**已核**）。
- **什么不会被推**：非原创——百科式概念介绍、备忘/书摘/笔记类、**没有个人研究、洞察、实践体验的内容**（[官方帖 2022-01](https://juejin.cn/post/7049199895575527437)，**已核**）。
- **曝光持续**：搜索长尾有效；首页推荐脉冲数天。技术文在百度权重也高。
- **新手初始曝光**：无特殊扶持期说法；**官方活动是新手的主要流量杠杆**——日新计划/金石计划等（见 §4）。

## 3. 官方规矩

**① 推荐与原创标准（已核，见 §2 引用的官方小册与官方帖）**：原创/本人翻译是硬门槛；技术相关；有个人实践。

**② 引流带货边界（官方小册口径，已核）**："掘金原则上不支持在文章中引流带货，但本着服务用户原则**不禁止**，前提是符合引流规范以保障阅读体验"（[小册原文](https://juejin.cn/book/m_6844733795329900551/section/6876001660431400967)）。含义：产品链接可以放，但文章主体必须有独立的技术价值；满篇软文=违规。官方允许的变现通道是课程分销（[官方公告](https://juejin.cn/post/7100789069512343583)）。

**③ 违规与处罚（官方）**：社区通过主动发现+用户举报（"联系客服"）处理违规（[《在掘金不可以做哪些事？》](https://juejin.cn/post/6844903618403893261)，**已核**）。**刷赞官方通报先例**：锁定 6 名互刷用户，后台降权+违规登记+掘力值扣减（小册内通报，**已核**）。签约/评奖活动违规（刷量、抄袭）取消资格（[签约计划公告 2024-11](https://juejin.cn/post/7434698783642583059)，**已核**）。

**④ 活动规则（官方，已核）**：日新计划——上榜须**原创技术文且首发掘金**，面试/代码人生/产品经理类不参评（[规则帖](https://juejin.cn/post/7123120819437322247)）；金石计划——正文 ≥650 字，广告/洗稿/凑字数取消资格（[要求帖](https://juejin.cn/post/7288597328269115433)）。

**⑤ AI 内容**：未找到掘金单独的 AI 标识规定；国家《标识办法》2025-09-01 施行适用于站内 AI 生成内容。[**平台执行细则未核实**]

## 4. 真实打法（按产品类型）

**开发者工具 / SDK（本平台最强场景）**

1. **第一步**：写"用 XX 解决 XX 的完整实践"——真实项目、真实数据、踩坑与解法。产品作为工具出现在实践里，不是文章主角。
2. **账号**：个人号（真名或惯用 ID）；发文前先完善资料与历史（空号首文转化弱）。[**二手**]
3. **参加官方活动拿首波流量**：日新计划（首发原创）或金石计划，上榜有官方流量位。
4. **见效周期**：首页推荐当天到三天见分晓；搜索长尾数周起效。**有作者公开过一个月运营数据复盘**（[实测复盘 2024-02](https://juejin.cn/post/7331684753664131123)，**作者自述**）——规律：垂直发文的数据累积明显优于杂发。
5. **失败的样子**：转载/拼凑文直接不进推荐；上首页后大改导致掉出；文末硬广触发举报。

**SaaS / 效率工具**：写技术向的深度评测/集成方案（"我们把 XX 接入了生产环境"），产品链接放文末"相关资源"区。

**消费品 / 一人公司**：掘金只适合有技术故事的产品（"我如何一个人写出 XX"）；纯消费品类不在此平台。

## 5. 死路

1. **搬运/洗稿**：非原创直接不推荐 + 举报通道成熟；洗稿在金石类活动明文取消资格（§3④）。
2. **互赞群**：官方锁定降权+掘力值扣减的通报先例在前（§3③）——掘金的处罚是留痕的（违规登记）。
3. **纯软文**：无独立技术价值的产品文，"原则上不支持引流带货"的反面就是它；被举报即处理。
4. **上首页后随手编辑**：可能掉出首页且不可逆（§2）。小修错别字也慎重。[**作者实测，非官方明文**]
5. **蹭热点水文**：百科式概念介绍被官方点名"不会推荐"。

## 6. 这里的人怎么说话

- **语气**：工程化、精确、有代码有图。先给结论和效果，再给实现；欢迎"我试了，结论是行不通"。
- **格式**：代码块、小标题、目录长文可接受（3000 字+正常）；配图用架构图/截图，不用营销图。
- **被尊重的表达**：给出完整可复现步骤、承认性能/局限、引用来源。
- **一眼营销的信号**：标题"赋能/解密/一文读懂"、正文无代码无数据、三段就上产品二维码、评论区只有"学习了"。
- **忌讳**：标题党（社区耐受度极低）、抄官方文档改写、假装实战。
- **好的开头长什么样**（按社区高赞模式还原，[非逐字引用]）：
  - 数据式："压测下来 QPS 从 1200 到 8600，改动的核心只有一个连接池参数。先给结论。"
  - 踩坑式："这个坑让我们线上 rollback 了三次，最终定位到是 SDK 的一个默认行为。"
  - 反直觉式："网上所有教程都让你先装 XX，但我们的测试里它是慢的主要原因。"

## 7. 账号与节奏

- **新号直接可发**，但首发原创质量决定账号起点（审核通过才有推荐资格）。
- **频率**：周 1–2 篇深度文 > 日更水文；官方活动期跟着活动节奏走。
- **时段**：工作日早 9–10 点与午休（开发者摸鱼高峰）。[**未核实**]
- **账号资产**：掘力值（违规扣减）、签约作者/优秀作者身份、活动获奖记录。

## 8. 风控与踩线

- **平台怎么识别**（已知）：人工审核前置（每篇过审才推荐）；举报通道；互赞行为锁定（官方通报）。[**推测**：发布频率异常、同质内容的账号级识别。]
- **踩线信号**：文章"已发布"但搜索不到（未过审或被限）；数据异常平淡（降权）；掘力值变动。
- **被处理了怎么办**：联系客服申诉（官方通道）；**更糟的动作**：换号重发（违规登记在实名/设备层 [**推测**]）、继续互赞（登记叠加）。

## 9. 怎么衡量有用

- **能拿到**：阅读、点赞、评论、收藏、粉丝（创作者后台）。
- **拿不到**：文内产品链接的出站归因（可自建短链带参解决）。
- **什么算"被问到"**：评论区问"这个工具怎么装/收费吗"；私信技术咨询（技术咨询=最强购买信号）。
- **常见误读**：把点赞当线索（技术文的赞是"学到了"，评论提问才是需求）；一篇爆款就日更冲量（稀释垂直标签）。

## 10. 适不适合

- **适合**：开发者工具、SDK、API、技术基础设施；有真实技术实践可写的团队；目标用户=前端/后端/AI 工程师的产品。
- **不适合**：非技术受众产品；没有真实项目实践支撑的"评测"（会被识破）；只想发软文的团队。
- **搭配**：掘金发实践长文（信任）→ 知乎答选型问题（决策）→ 公众号沉淀；与 GitHub 仓库互链（技术文↔README）是国内 devtool 标准闭环。

## 11. 发完之后怎么跟

掘金的跟进是**接住评论区里的技术问题**。

- **场内**：发文当天盯评论，技术问题当天答；答得越具体，文章越容易被加权。
- **第 3 天**：把评论里的问题整理成补充章节更新到文末（编辑要克制，避免掉出首页）。
- **第 14 天**：去同话题的他人文章下留有价值的评论，这是被发现的主要入口。
- **第 45 天**：参加官方活动时，把旧文重新整理成系列。

**禁忌**：不要互赞；不要发完就不管（掘金的推荐有持续观察期）。
