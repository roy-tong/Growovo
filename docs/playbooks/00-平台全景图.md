# 平台全景图

> 建图：2026-11-03 · 用途：**导航**，不是结论。每个平台的具体打法在各自的平台手册里。
> 一句话读法：这张表回答"有哪些地方可以去"，手册回答"去了以后怎么活"。

---

## 一、怎么用这张图

平台不是越多越好。**一个产品通常只需要 2–3 个平台**，多出来的都是浪费。

选平台的时候按这个顺序问：

1. 我的用户在哪个地方**已经在讨论我这类问题**？（不是"哪个平台流量大"）
2. 那个平台**让不让我这样做**？（明文禁止自动化的，只能人工）
3. 做完**能不能看到结果**？（看不见数据的平台，做完也不知道有没有用）

三个都能过，才值得投时间。

## 二、海外

### 核心平台（做技术/开发者产品绕不开）

| 平台 | 它是什么 | 分发靠什么 | 能自动到哪 | 适合谁 |
|---|---|---|---|---|
| **GitHub** | 开发者找工具、看代码、报问题的地方 | 搜索 + trending + 关系链（star/fork/issues） | 全自动（官方 API） | 开发者工具、开源项目、SDK |
| **Hacker News** | 技术圈的注意力中心 | 榜单投票，一次机会，掉下去就没了 | 只能人工 | 个人作品、技术观点、有数据的文章 |
| **Product Hunt** | 新产品的发布舞台 | 当日投票排名 + 编辑推荐 | 只能人工 | 面向早期采用者的新产品 |
| **Reddit** | 无数个自治社区 | 各 sub 自己的规则 + 站内投票 | 半自动（受各 sub 规则约束） | 有明确垂直人群的产品 |
| **X** | 公开的对话广场 | 转发 + 算法推荐 | 半自动 | 创始人个人品牌、build in public |
| **LinkedIn** | 职业身份网络 | 关系链 + 算法推荐 | 半自动（自动化加好友/私信会被罚） | B2B、企业服务、招聘相关 |
| **dev.to** | 技术长文社区 | 标签 + 首页推荐 + 搜索引擎 | 全自动（有 API） | 技术产品、教程型内容 |
| **Indie Hackers** | 独立创业者社群 | 社区讨论 + 产品页面 | 半自动 | 独立产品、一人公司 |

### 重要平台（按产品形态选）

| 平台 | 它是什么 | 分发靠什么 | 能自动到哪 | 适合谁 |
|---|---|---|---|---|
| **YouTube** | 视频搜索库，长期资产 | 搜索 + 推荐 | 人工（上传可走 API） | 需要演示的复杂产品、教程型 |
| **Google SEO** | 长期复利的分发 | 搜索排名 | 全自动（建站与内容） | 有明确搜索需求的产品 |
| **Newsletter 投稿** | 精准但窄的直达 | 编辑采纳 / 付费版位 | 半自动 | 有清晰读者画像的产品 |
| **软件目录站**（G2/Capterra/AlternativeTo） | B2B 采购决策入口 | 收录 + 评价 + 品类排名 | 半自动 | SaaS、企业软件 |
| **Stack Overflow** | 技术问答 | 回答质量与投票 | 全自动但高风险 | 开发者工具（只建议回答问题，不建议推广） |
| **Discord / Slack 社群** | 深度关系 | 群内互动 | 半自动 | 已有社区的产品 |
| **Bluesky / Mastodon** | 早期技术人群 | 时间线 + 转发 | 半自动 | 技术产品、隐私敏感产品 |
| **TikTok** | 大盘短视频流量 | 算法推荐 | 只能人工 | 消费类、面向大众 |

### 海外小结

**做开发者工具**：GitHub（主）+ Hacker News（一次发射）+ dev.to（长尾搜索）
**做独立产品**：Indie Hackers + X + Product Hunt（一次发射）
**做 B2B**：LinkedIn + 软件目录站 + SEO + Newsletter

## 四、按产品类型怎么组合（起手式）

| 产品类型 | 主战场 | 补充 | 一次性发射 |
|---|---|---|---|
| 开发者工具 / 开源项目 | GitHub | dev.to、掘金、V2EX | Hacker News |
| 独立开发者产品 / 一人公司 | 即刻、Indie Hackers | X、小红书 | Product Hunt |
| B2B / 企业服务 | LinkedIn | 知乎、软件目录站、SEO | 行业媒体 |
| 效率工具（面向大众） | 小红书 | 知乎、少数派、B站 | 微博 / 36氪 |
| 消费类 | 抖音、小红书 | B站、视频号 | 新品发布话题 |

**注意两件事**：

1. **"一次性发射"和"长期获客"要分开算**。发射是一次性的曝光，别拿它证明渠道能力；长期获客看的是"能不能每周稳定带人来问"。
2. **国内和海外不能照搬**。同一个产品在国内的定位可能完全不同——小红书讲"生活场景"，GitHub 讲"技术价值"。
