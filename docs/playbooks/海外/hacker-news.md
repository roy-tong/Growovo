# Hacker News

> 一句话：技术圈最大的注意力广场，一次性的，给的是信誉不是客户 · 研究日期 2026-11-03
> 官方口径：**已核**（newsguidelines / showhn 原文，2026-11-03 抓取，见 `docs/risk/hackernews.md`）
> 自家实测：**有**（Verovo Show HN 被判 genAI kill，2026-10）

---

## 1. 这里是什么地方

**谁在这里**：工程师、创始人、研究员、少数写技术博客的人。整体水平比一般技术社区高，也尖酸得多。很多人从 2007 年就在，看过的"颠覆性产品"比你看过的帖子多。

**他们来干什么**：
- 早上上班前刷一下，看看昨天行业出了什么事
- 看到有意思的项目点进去挑毛病
- 争论实现细节（这是他们最享受的部分）
- 少数人来找工作或招人

**它在这门生意里的角色**：**注意力 + 信誉**，不是转化。一次成功的 Show HN 能带来几千次访问、几十条评论、几百个 star，但这些人在接下来两周内几乎不会掏钱。它真正的价值是：让**该看到的人**知道你在做什么，以及让你在搜索结果里留下一个体面的痕迹（HN 的讨论页在 Google 上排名很高，几年后还有人点进来）。

---

## 2. 内容怎么被看见

**分发机制**：纯投票 + 时间衰减。首页 30 个位置，每个位置的得分按"票数 / 时间^1.8"算，所以新帖有机会，老帖掉得很快。

**什么会被推上来**：让工程师觉得"这个我得说两句"的东西。具体是三类：
- 有反直觉结论的技术文章（"我们把 X 换掉之后慢了 3 倍"）
- 自己做的、能用的小工具
- 对行业事件的尖锐观点

**曝光能持续多久**：短。一个帖子的生命周期大约 6–12 小时，掉出首页基本就没人看了。**但**搜索流量是长期的——Google 上搜技术问题时，HN 讨论页经常在前三，所以一篇文章的"资产价值"比"当日曝光"重要。

**新号有多难**：很难。新账号发的帖子初始权重低，容易被直接判定为推广。老号的 Show HN 通过率明显更高。

## 3. 官方规矩（原文，已核）

来自 [newsguidelines.html](https://news.ycombinator.com/newsguidelines.html) 与 [showhn.html](https://news.ycombinator.com/showhn.html)，2026-11-03 抓取：

| 原文 | 中文意思 |
|---|---|
| *"Please don't use HN primarily for promotion. It's ok to post your own stuff part of the time, but the primary use of the site should be for curiosity."* | 别把 HN 当推广渠道。偶尔发自己的东西可以，但你来这儿的主要目的应该是好奇 |
| *"Please don't put generated text in HN posts. Write your text yourself—HN is for sharing between humans. For the same reason, please don't automate posting."* | **不要放生成的内容，自己写。也不要自动发帖** |
| *"Don't post generated text or AI-edited text."* | 评论同理，**AI 改写过的也算** |
| *"Don't solicit upvotes, comments, or submissions."* | 不要求票、求评论、求提交 |
| *"Please don't delete and repost."* | 被删了不要删了重发 |
| *"Please don't create accounts routinely."* | 不要批量注册账号 |

**Show HN 的惯例**（非硬性规则，但违反会被喷）：只能发**自己的**东西；标题不超过 80 字符；发出来一小时内要有第一条补充说明。

**违规后果**：帖子被 flag → 变灰 → 掉出首页（dead）。账号可能被降权（你的帖子别人看不见）。严重或重复会被封号。

## 4. 真实打法

### 对开发者工具

**主线：Show HN。** 一次，最多一年两次。

做对的样子：
1. 标题写"你做了什么"，不写"为什么你该用"。例：`Show HN: I built a CLI that catches LLM output errors before they ship`
2. 首评自己写，讲三件事：为什么做（你被什么坑过）、怎么做（技术路线）、哪里不行（诚实说局限）。**这一段比帖子本身重要**，很多人先看首评再决定要不要点。
3. 发出去后两小时守在现场，每条评论都回，包括骂你的。
4. 有具体数据就给：处理了多少条、错了多少、比现有方案快多少。

**预期**：好的话几百到两三千访问，几十条评论，几十到几百 star；差的话零评论。**方差极大，一次不能说明任何问题。**

### 对技术观点/长文

比 Show HN 稳。写一篇"我们踩过的坑"式文章，附具体数字和代码，发链接。这类帖子不需要产品，不容易被当广告，而且搜索寿命长。

**关键**：文章里得有别人没有的东西——你们的内部数据、你们的失败、你们的实测对比。转述别人观点的文章没人看。

### 对个人品牌（最慢但最稳）

在评论区答题。找你们专业领域的新帖，认真回答，别带链接。做三个月，账号权重和辨识度都上来了。之后你发东西，有人认你。

这条路的成本是时间，回报是**以后每次发东西的初始分不一样**。

## 5. 死路（看着有理其实没用）

| 做法 | 为什么没用 |
|---|---|
| 群发链接、多个账号互相顶 | 投票模式会被识别；flag 之后帖子直接死，账号跟着降权 |
| 用 AI 写 Show HN | **明文禁止，而且有分类器**。自家事故：Verovo 的 Show HN 被判 genAI 直接 kill（2026-10） |
| AI 写完再"改写一遍" | 规则里写了 *AI-edited* 也算。改写比直接生成更容易被判（半人半机的文本特征更怪） |
| 新号第一次发就是推广 | 新号 + 推广 = 双重扣分，基本没曝光 |
| 被删了换个标题重发 | 官方明说不要，而且是加重情节 |
| "求支持，我们上了首页" | 求票是明令禁止的，且社区极度反感 |
| 用 HN 当客服渠道 | 大家是来讨论的，不是来帮你排查 bug 的 |

## 6. 这里的人怎么说话（人味）

> 这一节决定你的帖子是"被讨论"还是"被踩下去"。

**语气**：短句、直白、不修饰。可以自嘲，不能自夸。英文写作上偏向"工程师笔记"而不是"产品发布稿"。

**被尊重的表达**：
- 具体数字："把 p99 从 2.1s 降到 340ms" 而不是 "大幅提升性能"
- 承认局限："这个方案在超过 10 万条记录时会退化成 O(n²)，我没解决"
- 说清楚做了什么取舍："我选了 SQLite 而不是 Postgres，因为单机部署更简单，代价是不能水平扩展"
- 自嘲："我知道这玩意儿看起来像 2009 年的东西"

**一眼看出是营销的信号**（逐条避免）：
- 形容词堆砌：revolutionary、seamless、powerful、cutting-edge
- 感叹号
- "We're excited to announce..."
- 通篇没有一句"缺点"
- 标题里带 emoji
- 第一段是公司介绍而不是问题

**好的开头长什么样**（真实风格，不是模板）：
> "Our billing pipeline double-counted retries for about six weeks before anyone noticed. This is what I built to catch it."

> "I got tired of reading JSON logs, so I wrote a thing that turns them into a timeline. It's 400 lines of Python and probably breaks on Windows."

**忌讳**：
- 把 HN 当免费广告位（这是最容易被喷的一条）
- 在评论里反复提自己的产品
- 用"我们团队"这种公司口吻——这里默认是个人在说话

## 7. 账号与节奏

- **新号**：先评论两三周，攒点 karma，再考虑发帖。直接发推广基本没戏。
- **频率**：一天最多一次提交；评论不限，但别刷。一周有一两次有质量的参与就够了。
- **时段**：美东工作日上午（北京时间约 21:00–23:00）。周二到周四最好，周末流量低。
- **账号资产**：karma、历史帖子、评论记录。老号的帖子上首页概率高很多，这是长期积累的东西，别为一次推广糟蹋掉。

---

## 8. 风控与踩线

**平台怎么识别**（已知 / 推测分开）：

| 手段 | 性质 | 说明 |
|---|---|---|
| genAI 文本分类器 | 已知（自家事故） | 机打和 AI 改写的文本都会被判。2026-10 Verovo 亲历 |
| 社区 flag | 已知 | 推销感重的内容被 flag 后变灰、掉出首页 |
| karma 与账号历史 | 已知 | 新号低 karma 发 Show HN 通过率低 |
| 投票模式异常 | 推测（行业通用） | 短时间同源投票会被识别 |
| 多账号关联 | 推测 | 同设备/同 IP 行为模式关联处理 |

**踩线的信号**：帖子发出去 30 分钟零评论且排名不动；被标 dead；账号新帖无人可见。

**被处理了怎么办**：
1. **不要重发**（明文禁止，且是加重情节）
2. 不要换号（关联判定，一起废）
3. 停两周，去评论区认真答题，把账号信誉养回来
4. 如果认为误判，走 hn@ycombinator.com，说明情况，不要争辩

## 9. 怎么衡量有用

**能拿到**：帖子的分数和评论数（公开可见）、评论里提到你产品的次数、HN 带来的访问（要靠自己的链接追踪）。

**拿不到**：多少人看了没点、有多少人看了标题就走了。

**"被问到"长什么样**（这是真正的信号）：
- "How does this handle X?" —— 具体场景的问题
- "Can I use this for Y?" —— 有人在想自己的用例
- "What's the license?" —— 有人在考虑真的用
- 有人主动发邮件或在 GitHub 开 issue

**常见误读**：
- **上首页 ≠ 有用户**。几千次访问可能只换来几十个 star，star 里还有一半是收藏夹吃灰。
- **评论多 ≠ 反应好**。HN 的评论经常是来挑毛病的，这其实是好事——说明他们认真看了。
- **一次结果不能推广到下一次**。方差极大，别用一次成功或失败下结论。

---

## 10. 适不适合

**适合**：
- 开发者工具、CLI、库、SDK
- 有实测数据的技术文章
- 创始人的技术观点（建立个人信誉）

**不适合**：
- 消费类产品（这里没人关心）
- 需要视觉演示才能理解的东西
- 长销售周期的 B2B（这里的人不是采购决策者，或者是但不在这儿做决策）
- 任何需要"包装"才能说清楚的产品

**搭配使用**：HN 发完之后，把访问引到 GitHub（让 star 和 issue 沉淀下来），再在 dev.to 写一篇长文承接搜索流量。HN 是一次性的，后面两个是长期的。

---

## 11. 发完之后怎么跟

HN 的帖子 24 小时就没了，但**评论区里的人还在**。

- **场内**：发出去两小时守现场，每条评论都回（包括挑刺的）；第 7 天帖子若还在被讨论，补一条"后来发现……"。
- **场外**：不要在 HN 私信推销。有人留了邮箱或仓库，才一对一联系。
- **第 3 天**：给说过"我会试试"的人发一句"试了吗，卡在哪"（走邮件或仓库 issue，不在 HN）。
- **第 45 天**：还能联系上的人，才是 HN 真正的产出。

**禁忌**：不要为了续命顶帖（官方反对）；不要换号重发；不要在评论里反复贴链接。
