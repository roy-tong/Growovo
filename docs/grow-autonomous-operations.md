# Growovo 自动运营（2026-11-14）

输入产品事实与增长目标后，Growovo 用本机已登录的 Codex CLI 生产内容，经过独立审稿后暂存；执行器按既有授权和日配额发送，读回自己的帖子指标并生成每日结果。用户通过 `decide continue|optimize` 决定是否调整策略。

## 启动与使用

```bash
# 新 v2 run 默认启用 Codex 内容供给；launch 仍会检查现有授权
python3 mkt.py grow launch my-run --facts facts.json --goal awareness.followers --channels x --handle my_account
# 原有 run 升级（不改变 go、动作范围、账号授权或日配额）
python3 mkt.py grow agent my-run
# 手动验证内容链：仅发现、生成、审稿、入队，不发送
python3 mkt.py grow produce my-run --max-items 1
# 按已有契约开闸后，前台常驻；异常暂停，Ctrl-C 停止
python3 mkt.py grow daemon my-run --interval 30 --no-deliver
python3 mkt.py grow daily my-run
python3 mkt.py grow decide my-run --action optimize --dry-run
python3 mkt.py grow decide my-run --action optimize --note '根据日结果调整'
```

`agent --disable` 停止自动生产，不改变既有待发队列。全局 `mkt pause` 停止执行。需要时通过 `GROWOVO_CODEX_BIN` 指定 CLI 绝对路径；凭据继续由本机 Codex 管理，不写入 run 文件。

## 一轮运行实际做什么

1. 检查任务状态、暂停、日期和并发锁。
2. 按今天的配额减去已发与可执行待发内容，计算缺口。
3. X 从产品关键词搜帖、读取作者主页、按主题和 KOC 关系排序。粉丝数属于 1k–50k 不再足以证明是相关 KOC；需要领域背景或持续的相关内容。
4. Codex 审核产品、账号背景和帖子是否真正契合。政治预算 reconciliation 等同词异义的内容不能进入发信队列。
5. Codex 写作，再进行独立审稿。最多两轮重写；不要求每条都加问题，也不为了规则分数编造个人经历或数字。
6. 硬性格式、长度、重复目标和发布门禁照常生效。模型不能更改目标、渠道、排期或授权。正文与审稿记录的 SHA-256 一起保存。
7. 复用原队列执行器，逐条发送并回读。X 单条原创帖也已支持队列，并绑定稳定的账本目标，未知结果禁止自动重试。
8. 每日刷新自己的帖子指标，附截图证据，独立帖子去重后生成复盘建议。应用过的证据不会重复调参；周结算只建议加量，用户决定是否执行。

默认每轮最多生产 3 条，每日最多尝试 12 个内容任务，每个候选最多审核 3 次、生成/审稿最多 2 轮；单次 CLI 调用超时 180 秒。失败记录到 `production.jsonl` 并退避 30 分钟。待发内容过期、审稿失败或缺候选均如实显示，不算完成。

Email 不猜测地址，联系人来自事实包的 `outreach_contacts: [{"email":"...", "context":"为什么相关"}]`；没有联系人就保留缺口。同日多渠道分别建队列。结果单默认落本地 Markdown/HTML；`--deliver` 目前仍只生成本地邮件草稿，不等于邮件已送达。

## 运行可靠性

- 账号=浏览器登录态：写动作在授权门之后自动检测目标站点登录态（`core/session_gate.py`，结果带 300 秒缓存，零凭据）；缺失明确报 rejected，不会落到 vendor 失败后的 indeterminate；`grow doctor` 逐渠道报告登录态（未登录是 blocker，调试 Chrome 不在是 warn）。
- tick、生产及关键状态变更使用操作系统文件锁，run 文件原子替换；进程崩溃后锁自动释放。
- 目标周期结束后停止发送；执行结果未知或意外异常转为 `needs_attention`，不盲目重试。
- 读和写都复用 X 标签页；不每次新开页或关闭用户正在使用的自动化页。
- 心跳写入带时区时间，历史本地时间按本机时区解释；不能把未来时间算成刚执行过。
- macOS 的 Documents 权限可能阻止 launchd。`grow install` 仅生成配置时不会启动；安装成功也不再等同于心跳已验证。前台 daemon 可在当前有权限的终端运行。

## 实测与限制

本机 ChatGPT 登录已验证。真实 Codex 完成过生成、独立审稿、入队；测试候选与临时工作区明确标记为合成数据，没有发送。真实 X 回复读数已验证并保存截图，父帖与自己的回复没有混算。

账号匹配与内容质量仍需要每天用真实反馈检验；互动是代理指标，不能归因证明新增关注或付费。模型调用、X 登录态和设备在线是持续运行条件；没有合格候选时允许当天少发，不以降低标准换取发布数量。读数的长期校准等级保持原值，不因为一次实测自动升级。

## 0.14.0 整合说明

- 策略编译保存与目标、阶段、明确渠道范围匹配的战术组合。组合是可追溯建议，不扩大真实执行的动作与配额。
- 提前备货跨周使用各自周配额；超过两天的陈旧内容不会阻止补货。
- 登录态必须有已登录界面标记；页面加载或验证状态不明时不能放行。
- 对手监控只报告可见正文变化，过滤脚本、空页和验证页；变化需复核后才能解释为涨价、故障或机会。
- 定时任务绑定 MKT_HOME；发布前生成的配置建议重新生成。事实包保存绝对路径，安装版包含经验记录。
- 目标阶段推进必须带 --note 证据；商单未知不等于零，发出不等于对方互动。
