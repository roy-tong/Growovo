## Case template

A legitimate Growovo case must contain:

1. **Preregistered goals and gates** — "what counts as pass, what counts as dead" written before launch; decision lines never move afterwards;
2. **Four phases** — define (readiness + positioning) / build (assets) / run (channel execution) / measure (outcome definitions);
3. **Minutes ledger** — operator and human tracked separately; the human budget is a hard constraint;
4. **Two-layer results** — platform action success ≠ business outcome; approximations must be labeled;
5. **Lesson captured** — a case must answer "what mechanism did this price buy";
6. **Status and evidence level** — in progress means in progress, zero means zero.

## Third-party cases

External cases use an opt-in case-note mechanism: after a free task or an engagement, clients voluntarily authorize publication; deliverables (audit reports, fix records, data) come before narrative. The first external case will appear here once authorized.

## How to verify these cases

All three are self-dogfood: the vendor is also the client, which makes them easy to write and hard to trust. [How to verify](verify.md) lists what you can check yourself (commits, stars, URLs, tests), what you have to take on faith (minutes ledgers, internal decisions), and why the star count needs its own paragraph. **Read that page before the cases.**
