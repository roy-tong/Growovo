## 案例模板

一个合格的 Growovo 案例必须包含：

1. **预注册目标与门禁**——开跑前写死「什么算过、什么算死」，判定线不事后挪动；
2. **四阶段过程**——定（readiness + 定位）/ 造（资产）/ 跑（渠道执行）/ 量（结果口径）；
3. **分钟台账**——operator 与 human 分开记，人工预算是硬约束；
4. **结果两层分开**——平台动作成功 ≠ 业务结果；近似口径必须标注；
5. **教训沉淀**——案例必须回答「这次代价换来了什么机制」；
6. **状态与证据等级**——进行中就是进行中，零就是零。

## 第三方案例

外部案例采用 opt-in 案例笔记机制：客户在免费任务或委托交付后自愿授权公开，交付物（审计报告、修复记录、数据）先于叙事。第一份外部案例将在获得授权后出现在这里。

## 怎么核验这些案例

三份案例都是自营 dogfood——卖方同时是客户，这使它们容易写、难被信。[如何核验](verify.md) 逐条说明哪些能自己查（commit、star、URL、测试）、哪些只能听我们说（分钟台账、内部决策），以及 star 数字为什么需要单独一段说明。**建议先读这一页，再读案例。**
