# 平台运营策略 v2（2026-11-21）

> 上一版是 2026-11-17 的《图文内容策略采集报告》，那轮把经验库从 210 条扩到 594 条，回答的是「别人怎么做」。
> 这一版补的是**机制层**：平台在 2026 年把分发和风控改成了什么样，我们的哪条做法因此失效、哪条因此更值钱。
> 只写能在 2026 年找到出处的；单源、二手、社区逆向的单独标 `lead`，不进自动门禁。

## 怎么读

每条结论后面跟三样东西：`grade`、`as_of`、来源。

| grade | 含义 | 进不进代码 |
| --- | --- | --- |
| `official` | 平台规则页、官方公告、官方文档原文 | 可进门禁 |
| `craft` | 至少两个独立来源复现过的做法 | 可进门禁，需 2 源 |
| `lead` | 单源二手、社区逆向、我们自己观察 | 只做线索，不改默认参数 |

`as_of` 是这条信息对应的时点，不是我们查到的时点。平台改规则时，先看 `as_of` 再看结论。

## 公众号

### 2026 年的分发机制

- 公域推荐已占阅读量的 70–90%，其中推荐流 50–60%；订阅关系的权重继续下降。`craft`｜`as_of 2026-08`｜[jzl](https://g.jzl.com/news/19196)、[askuzu](https://www.askuzu.com/blog/post/484.html)
- 新文章进约 200–500 次曝光的初始流量池，按数据决定是否加推（赛马）。`craft`｜`as_of 2026-08`｜[火炬树](https://torchtree.com/post/wechat-content-forms-2026-guide/)、[woshizmt](http://www.woshizmt.cn/category/weixin/3234.html)
- 算法权重：完读率 35% > 分享 30% > 收藏 20% > 互动 15%。`lead`｜`as_of 2026-08`｜仅 jzl 一家给出具体百分比，其余来源只确认「完读率权重最高」，所以数字当方向看，不当公式用。
- 读者在 30% 进度前退出，会被判低质或标题欺诈。`lead`｜同上。这条解释了为什么「标题承诺」比「标题党」更危险：标题党换来的点击会在 30% 处流失，反而压低整篇权重。
- 搜一搜日均搜索量 8 亿，内容生命周期从 24 小时拉长到 7 天以上，新关注约 40% 来自搜一搜。`lead`｜`as_of 2026-07/08`｜[askuzu](https://www.askuzu.com/blog/post/484.html)、[woshizmt](http://www.woshizmt.cn/category/weixin/3234.html)。40% 这个数字单源，标为假说。

### 因此改怎么做

1. **标题只承诺正文能兑现的事**。完读率是第一权重，标题骗来的点击会在前 30% 流失，净效果为负。
2. **首屏三段给结论**。读者判断「要不要读完」发生在开头 200 字内，把结论、证据、边界一次说完，再用剩余篇幅展开。
3. **结尾埋搜索词**。搜一搜是唯一在 7 天后还在给量的入口；每篇结尾用一句自然的话复述「这篇解决什么问题」，让标题之外的关键词也能命中。
4. **周更 1–3 篇不变**。推荐池不看更新频率，看单篇数据；日更水文会稀释账号的内容质量画像。这条与 v1 一致，2026 年没有反向证据。

### 2026 年的新红线（详见风控卡）

- 2026-03-27《微信公众平台运营规范》新增「非真人自动化创作行为」专项，明确把「脚本、程序托管等自动化方式批量、连续发布」列为违规。`official`（媒体转述官方规范条文）｜`as_of 2026-03-27`｜[搜狐](https://m.sohu.com/a/1038473275_122279841)、[澎湃](https://www.thepaper.cn/newsDetail_forward_32934993)
- 2026-05 起导流检测升级为独立维度，简介/正文/评论/消息里的联系方式、外链、二维码都会让文章标「不符合内容推荐条件」。`craft`｜`as_of 2026-05`｜同上两篇的后续报道。

## 小红书

### 2026 年的分发机制

- 分发改成「AI 合规审核 + 数据闯关」双轮：先过合规模型，再进流量池。`craft`｜`as_of 2026-10`｜[简盒](https://www.jianhebox.cn/article-xiaohongshu-algorithm-2026.html)、[hashmeta](https://hashmeta.com/cn/posts/xiaohongshu-algorithm-2026-traffic-distribution)
- 所有新笔记统一进 200–500 曝光的初始种子池，**取消老号权重优先**。`craft`｜同上。这条对我们最重要：账号历史不再提供起跑优势，单篇质量决定一切。
- CES 新增「搜索点击率」和「阅读完成率」两个因子，搜索流量占比继续上升。`craft`｜同上。

### 因此改怎么做

1. **封面上的关键词就是搜索入口**。搜索因子进 CES 之后，封面文字不只是点击诱饵，还是检索匹配字段；封面写「XX 产品实测」比写「我后悔了」更容易被搜到。
2. **前 20 字决定点击，前 100 字决定完读**。小红书正文折叠前只露两行，把「谁、什么问题、什么结果」压在开头。
3. **老号不养老**。取消老号权重优先后，连续低数据的账号不会自动获得推荐，需要按新号标准重做选题。
4. **3–5 篇/周不变**，但每篇必须有独立素材。同素材多号或多次发布的相似度阈值是 50%（见风控卡），「一稿多改」现在有硬风险。

### 2026 年的新红线（详见风控卡）

- 2026-04 新规「人工 + AI 双审」，8 条红线：私域导流、AI 未标注、广告极限词、实名与环境一致、重复度、诱导互动、未报备商业推广、虚假数据。`official`（媒体逐条转述平台规则）｜`as_of 2026-04-27`｜[南京优创思维](https://www.ucsiwei.com/news/xiaohongshu-2026-april-new-rules-8-red)
- AI 未标注三级处罚：初犯警告 + 限流 7 天，二次禁言 30 天，三次永久。`official`（同上转述）

## 抖音

### 机制

- 图文与短视频都走初始流量池赛马，这一点 2026 年未变。`craft`｜沿用 v1，多源。
- 2025-09-01《人工智能生成合成内容标识办法》生效，未主动标识的 AIGC 内容会被平台加「疑似 AI 生成」标识并限流。`official`｜`as_of 2025-09-01`｜[中国科技网](https://www.stdaily.com/web/gdxw/2025-09/02/content_393775.html)
- 《社区自律公约》第 34 条「恶意导流」覆盖第三方平台账号、水印、logo。`official`（媒体转述公约条文）｜`as_of 2026-10`｜[NoobClaw](https://noobclaw.com/cn/blog/douyin-image-text-post-traffic/)

### 因此改怎么做

1. **AI 辅助必须主动标识**。不标识不会「不被发现」，而是「被发现后加标 + 限流」，且处罚记录留在账号上。
2. **画面里不出现其他平台的水印、logo、账号名**。剪辑素材从别处下载时最容易带进来，发布前逐帧看一遍角标。
3. **图文和视频分别建选题库**。同一选题在两种形态下的完播/完读逻辑不同，不能直接互转。

## 知乎

### 机制

- 回答的长尾搜索价值仍在：一条回答可以在数月内持续被搜到，这是知乎与其他平台最大的差异。`craft`｜沿用 v1，多源。
- 2026 年知乎官方规范原文本轮**没有查到**（登录墙 + 检索未命中）。所有 2026 年新规相关的说法都标 `lead`，不作为门禁依据。

### 因此改怎么做

- 选题从「用户会搜什么问题」倒推，不从「我想说什么」正推。
- 回答结构：先给结论，再给证据链，最后给适用边界。知乎读者对「只给结论不给过程」的容忍度最低。
- 不在回答里放联系方式或站外链接；需要承接时走平台内的「咨询」入口。

## X

### 2026 年的分发机制（这一节推翻了 v1 的旧权重）

- 2026-01 xAI 开源推荐算法（`xai-org/x-algorithm`），2026-08-13 公布默认权重。`official`｜`as_of 2026-08-13`｜[GhostReply 汇总](https://ghostreply.agency/blog/x-algorithm)
- **2023 年流传的「回复 = 27 倍点赞」已经作废**。2026-10-20 的权重文件里 reply 5.0、like 0.66（约 7.6 倍），2026-11-13 的版本 like 0.708。`official`（开源权重文件）｜同上再加 [Postory](https://postory.io/blog/x-algorithm-2026)
- 开源代码里**没有硬编码的链接惩罚**，CLICK_WEIGHT 为正（点开外链约 0.2）。`official`（代码）｜[FrameOS](https://frameos.studio/blog/twitter-algorithm)
- 但实测带外链的帖子中位互动接近零，2026-03 起对非 Premium 账号更明显。`craft`｜`as_of 2026-06`｜[searchsavvy](https://searchsavvy.in/x-algorithm-now-charges-for-visibility-heres-the-organic-workaround-that-still-works/)
- 2026-03 起回复点踩（not interested / misleading / AI-generated / spam）直接进回复排序。`craft`｜同上系列报道。

### 因此改怎么做

1. **回复仍是最高价值动作，但没有 27 倍那么夸张**。把「回复作者和活跃读者」当主策略，不要按旧倍数做产能规划。
2. **链接放首条回复，正文保持原生**。代码没有链接惩罚，但实测分发确实压低外链帖；这是「代码没写、产品在别处做」的典型，按实测走。
3. **不要做 automated likes / bulk follow**。这两条是 Automation Rules 明文禁止项，不是「风险较高」，是「禁止」。
4. **回复要经得起点踩**。AI 味重、答非所问、模板化的回复会被读者点踩，而点踩直接进排序——回复质量现在有即时反馈。

### 2026 年的成本变化（详见风控卡）

- 2026-02 起新开发者取消 Free/Basic/Pro 固定档，改 pay-per-use：约 $0.015/帖、**带链接 $0.20/帖**、自有数据读取 $0.001/次。`craft`（多家 API 服务商一致转述）｜`as_of 2026-02`｜[NetworkX](https://www.networkx.ai/blog/x-twitter-api-limits-in-2026-what-every-automation-user-needs-to-know)、[ClimbX](https://climbx.so/blog/x-api-limits)
- 带链接帖的单条成本是纯文本的 13 倍，这一条直接改变「链接放正文还是回复」的经济账：链接放回复，成本按回复计价，同时避开实测分发惩罚。

## Reddit

### 机制（发布侧）

- free tier 100 QPM；self-service 应用申请 2025-11-11 关闭；app label 2026-03-31 上线；用 Reddit 数据训练模型需书面批准。`official`（API 条款 + 官方公告转述）｜`as_of 2026-08`｜[RedditAPI](https://www.redditapis.com/blogs/reddit-bot-rules-2026)
- 2026 年各 sub 的账号门槛（社区逆向，非官方口径）：`lead`｜`as_of 2026-05/06`｜[soar.sh](https://www.soar.sh/blog/self-promotion-rules-by-subreddit-database)、[subredditanalyzer](https://www.subredditanalyzer.com/how-much-karma-do-you-need-to-post-on-reddit)
  - 小型 sub（<50K）：多数无门槛
  - 中型（50K–500K）：50–200 comment karma + 7–30 天号龄
  - 大型（500K–5M）：200–500 karma + 14–30 天
  - 超大（5M+）：更严，常要求人工审核
- CQS（Contributor Quality Score）为 Low/Lowest 时，即使 karma 达标也会被 AutoMod 拦截。`lead`｜`as_of 2026-04`｜[Upvote.net](https://upvote.net/blog/reddit-account-health)
- 9:1 自我推广规则仍在：每 10 条内容里最多 1 条是自我推广。`official`（Reddit 自助推广规则）｜多年未变。

### 因此改怎么做

1. **先选 sub 再定内容**，不要先写内容再找地方发。同一个产品在不同 sub 的接受度差异极大，且门槛是硬门槛。
2. **用 comment karma 而不是 post karma 养号**。多数 AutoMod 配置只看 comment karma，发帖涨的 karma 不算数。
3. **9:1 是底线不是目标**。实际执行按 20:1 更安全，因为版主会看历史发帖比例。
4. **发布前查 sub 规则页**，特别是 `Rule 3: No self-promotion` 之类的条款；每个 sub 的自我推广定义不同（有的算链接，有的算提及产品名）。

### 2026 年的关键变化：API 要关了（对发布侧同样致命）

- 2026-09-30 r/redditdev 官方时间表：2026-10-31 停止接受新 public API 申请；2027-01-12 开始切断未登记应用；**2027-03 全部 public API 关闭**；2026-11-13 RSS 停止支持。`craft`（多家二手一致转述官方帖）｜`as_of 2026-09-30`｜[Reduck](https://reduck.ai/use-cases/reddit-api-alternatives)、[BoomReddit](https://boomreddit.com/glossary/reddit-api/)
- 迁移目标是 Devvit（跑在 Reddit 内部的应用平台），**不适合外部发布工具**。

**这意味着 Growovo 的 Reddit 自动发布通道在 2026-03 之前必须改用人工发布或停止。** 这不是「策略调整」，是通道消失。详见风控卡。

## LinkedIn

### 机制

- 2026 年社区逆向阈值：连接请求 20–25/日、100/周、pending 邀请保持在 500 以下；新号先养两周，之后每周增加 5 个请求。`lead`｜`as_of 2026-07-20`｜[Yalc](https://www.yalc.ai/blog/linkedin-automation-limits-and-rules/)
- 浏览器插件式自动化是 LinkedIn 检测的主要触发源，比 API 调用更容易被封。`lead`｜同上。

### 因此改怎么做

1. **不装任何「自动化助手」插件**。这是目前 LinkedIn 封号最高频的原因，且封的是个人主账号。
2. **连接请求按周配额做，不按日**。日配额是平均数，周配额是硬顶；单日冲 25 个会在周末前触顶。
3. **pending 邀请 <500**：积压的未接受邀请会被平台当作骚扰信号。

## GitHub

### 机制

- 2026 年配额未变：认证 5000 请求/小时、未认证 60/小时、Search API 30/分钟、REST 二级限流 900 points/分钟、并发 100。`official`｜`as_of 2026-10`｜[GitHub Docs](https://docs.github.com/rest/using-the-rest-api/rate-limits-for-the-rest-api)、[Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-cloud/dev/dev-proxy/concepts/github-api-rate-limit-exceeded)

### 因此改怎么做

- 批量操作（建 issue、查仓库、跑搜索）必须读 `X-RateLimit-Remaining` 和 `X-RateLimit-Reset`，不要按固定间隔硬跑。
- Search API 的 30/分钟是最容易踩的坑：一个循环里查 50 个仓库就会触发，且 Search 配额与 REST 配额分开计算。
